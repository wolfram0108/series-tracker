## Релиз

Модульно-шинная система **выпущена и работает на проде** (этот сервер).
- `main` = новая система; тег **`v2.0.0`** + GitHub Release.
- Старая монолитно-агентная версия — тег **`legacy/v1-final`** (откат);
  старый фронт — `legacy_frontend/` (отдаётся по `/legacy`).
- Прод: systemd-юнит `series-tracker` (uvicorn :5000), деплой из `main`
  по [deployment.md](deployment.md).
- Тесты бэкенда зелёные (кроме намеренно красных `*_match_production` /
  `*_diff` / `test_sources` — нужны golden/прод-фикстуры; старой системы
  для сверки больше нет).

**Бэклог (не блокеры):** сквозной astar/anilibria_tv на реальной раздаче.

## Что починено в v2 (журнал ключевых находок)

Поведенческая матрица (полностью — [contracts/series_situations.md](../contracts/series_situations.md))
пройдена: торрент 62 ✓ / 5 ◐, VK 46 ✓ / 6 ◐, 0 нерешённых.

Торрент-конвейер:
- **R2** — re-add раздачи после удаления из qB не запускал конвейер.
- **R1/R3/P10** — скан не сверял файлы; исчезнувшая раздача оставляла фантом
  `is_active`; застрявшая (пауза 0%, без задачи) не перезапускалась.
- **Д1** — счётчик «скачано» не уезжал в SSE.
- **Д2** — удаление серии не прерывало in-flight yt-dlp/ffmpeg/перемещение и
  не сносило полуфайлы (принцип: удаление НИКОГДА не трогает готовые файлы).
- **F7** — при недоступном NAS `fs.verify` помечал всё ложно missing.
- **C9** — конвейерное переименование без per-series лока (гонка с reprocess,
  корень кривых имён `.mkv.mkv.mkv`).

VK:
- **R4** — обычный скан не сверял диск VK (`downloads.fs.sync`).
- **VF6** — `_remove_partial` не чистил реальные артефакты yt-dlp.
- **VP7/VL2/VL5** — `run_ffmpeg` писал неатомарно; битый кусок усыновлялся как
  готовый → теперь tmp→`os.replace`.
- **VF2** — обычный скан не сверял нарезанных детей.
- **VU11** — `ignored_seasons` писался, но не применялся в плане → починен.

TMDB: агрегирование числа серий по нескольким сезонам (многосезонник).

Остаточные ◐ (приемлемые): VU9 (приоритет не заменяет уже скачанное),
VP3 (живой репро yt-dlp «96% без файла» — по запросу), VP5/VS4 (рассинхрон

## После релиза (журнал)

2026-09-17:
- Имена файловой системы получили единое правило (`core/fsnames.py`,
  зеркало `web/src/lib/fsnames.ts`): путь сохранения, английское имя и
  оверрайды качества/разрешения нормализуются владельцем колонок
  (`catalog`), при перемещении (`library`) и в сохранённых путях
  (`settings`); в окнах добавления и свойств поля автоисправляются при
  вводе (`StInput kind`). Находка 67.

2026-09-02:
- Антибот-челлендж Cloudflare стал свойством транспорта, а не отдельного
  трекера: распознаётся по служебному заголовку одинаково для всех,
  вешается на сессию (`cf_challenge.arm`) и поднимает `ChallengeSeen`
  вместо ответа, прохождение и повтор собраны в одну точку, общую для
  запроса и для входа в аккаунт. User-Agent стал свойством сессии —
  клирэнс защиты действителен только в паре с ним. Kinozal, включивший
  защиту на контентных страницах, снова разбирается; RuTracker снова
  может войти после разлогина. Зеркала kinozal дополнены `kinozal.guru`.

2026-08-25:
- Торрент-сериалы: выборочная загрузка серий и сезонов. Состав раздачи
  строится по кнопке «Получить данные» (раздача добавляется в
  qBittorrent на паузе и разбирается правилами, закачка не начинается),
  отбор серий и сезонов идёт тумблерами композиции, запускает загрузку
  очередной скан. Память отбора ведётся номерами серий сериала
  (`series.ignored_episodes` + `ignored_seasons`), поэтому переживает
  замену раздачи; на файлы текущего релиза она проецируется колонкой
  `torrent_files.is_excluded`, из которой считаются приоритеты файлов
  qBittorrent. Качается только распознанное и не исключённое —
  нераспознанные файлы выключаются сразу и показаны в композиции
  отдельно с причиной.
- Планировщик VK-плана падал (`KeyError`) на кандидате с перевёрнутым
  диапазоном эпизодов (`episode_end < episode_start`, мусорный заголовок
  источника) — такие кандидаты исключаются из планирования.
- Сезон карточки сериала (односезонник) не учитывался при построении
  VK-кандидатов и в ответе `scan.composition` — резолв вынесен в единую
  точку (`core/season.py`), используется `rules.apply` и
  `rules.format_torrent_file`.
- Композиция VK: точечный переключатель у каждого эпизода дополнен вторым,
  тройного состояния, на уровне сезона (`PUT .../media-items/ignore-season`)
  — массово гасит/зажигает `is_ignored_by_user` текущих эпизодов сезона, не
  затрагивая `ignored_seasons` и будущие эпизоды.
- Загрузка VK-видео: при пустом файле от HLS-фазы (VK иногда не отдаёт
  хвостовые фрагменты, 404) — повтор без m3u8 (DASH/progressive, без
  параллелизма фрагментов).
- Шаг 3 конструктора профилей правил («Фильтры VK» → Настройки) терял
  введённые данные при сворачивании/разворачивании аккордеона (`v-if`
  пересоздавал компонент) — заменено на `v-show`.
- Скачивание `.torrent` с kinozal встало: поддомены доставки (`dl.*`)
  отвечают `520` и заглушкой «ведутся технические работы» с кодом `200`,
  тогда как основной домен файлы отдаёт. Выход sources наружу сведён в
  единую точку (`modules/sources/delivery.py`): живой хост выбирается в
  момент запроса (канонический хост ссылки → зеркала трекера → хост как
  написан), результат проверяется по объявленному виду (`page` /
  `torrent` / `json`), заглушка с кодом `200` файлом не считается. Ссылка
  раздачи остаётся идентичностью — `torrent_id` не меняется. Находка 68.
- Смена учётной записи трекера в настройках не применялась: сессия
  сбрасывалась только в памяти, а из БД восстанавливались куки прежнего
  аккаунта — запросы шли под ним (и под его суточным лимитом), потому что
  протухания не было и вход не запускался. Вход привязан к учётным данным
  отпечатком (`tracker_sessions.account_fingerprint`, миграция 0009) — и в
  БД, и в ключе кэша сессий; клирэнс антибот-защиты и UA от привязки
  свободны (они про клиента). Находка 69.

2026-10-19:
- Поддержка веб-видеоисточников (`web_video`) и провайдерная архитектура
  (`modules/sources/video_providers`, Р-25). Первый провайдер — Ruchime (`1.ruchime.org`)
  с каскадным зондированием плееров VK Video и AllVideo (Playerjs), поддержкой разрешений
  до 2160p (4K), детерминированными датами для уникальности `media_unique_id` и прямым
  потоком через шину `sources.video.stream` (изоляция модуля загрузок от сайтов/доменов).
- Пер-эпизодное разрешение: сохранение динамического качества каждой серии без перетирания
  серийным `resolution_override` при парсинге URL.
- В интерфейсе: поддержка веб-видео в проверке правил (`ParserTest`), вкладке истории
  (`StatusHistory`), динамические подписи обновления и проверка нейминга.
