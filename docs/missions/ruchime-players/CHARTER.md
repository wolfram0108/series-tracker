# CHARTER — Плееры 1.ruchime.org: любой источник, а не только VK

> Слой 1. Короткий, меняется редко. Читать ПЕРВЫМ. Прогресс — в ROADMAP.md.
> Старт 2026-10-20.

## Цель (одним абзацем)

Парсер `1.ruchime.org` жёстко зашит на два плеера: VK Video и AllVideo. Серия
«Практикуя ци сто тысяч лет» на VK закрыта настройками приватности, у 387-й
серии AllVideo уже нет (у 386-й ещё есть), а доступна она только в Kodik и
Vibix. Из-за этого эпизод без источника попадает в очередь с мёртвой ссылкой
VK, а система не говорит пользователю, что серии на VK нет. Цель миссии —
сделать плеер универсальным: парсер перечисляет плееры, которые реально есть на
странице релиза, проверяет каждый на доступность, отдаёт по кандидату на каждый
доступный плеер (выбор качества остаётся за планировщиком) и честно сообщает,
где серия доступна, а где нет.

## Целевой результат

```
страница серии 1.ruchime.org (release/<slug>)
   │  кнопки плееров: data-player="vk|allvideo|kodik|vibix"
   ▼
перечисление плееров (без хардкода имён)
   │
   ├─► VK        ── probe: страница video_ext.php → есть mp4_<N>?  ──► 2160p / ЗАКРЫТ
   ├─► AllVideo  ── probe: embed → есть file: (Playerjs)?         ──► 1080p
   ├─► Kodik     ── probe: embed → есть список серий?             ──► 360/480/720
   └─► Vibix     ── probe: браузер (SDK)                          ──► см. этап 5
        │
        ▼
   кандидат на КАЖДЫЙ доступный плеер  (source_url = ссылка плеера)
        │
        ▼
   планировщик (уже есть) выбирает лучший по приоритету качества
        │
        ▼
   скачивание: sources.video.stream → разбор ссылки плеера → поток
        ├─ VK        → https://vk.com/video<oid>_<id>          (yt-dlp)
        ├─ AllVideo  → embed → file: → mp4 на incvideo1.online (ffmpeg)
        └─ Kodik     → embed → POST /ftor → ROT18+base64 → HLS   (ffmpeg)
```

Отличие от текущего состояния: плееров не два, а «сколько есть на странице»;
плеер без доступного источника не подставляется молча; серия без VK видна как
серия без VK.

## Архитектура парсера и плееров (этап 8 и далее)

Парсер сайта — модуль приложения: он выполняет всю внутреннюю логику получения данных и отдаёт готовое на шину.
Плееры — общие модули, которыми пользуются разные парсеры.

```
шина: sources.parse / layout / coverage / video.scan / video.stream
   │
парсер сайта (ruchime, dunhuatv) — логика сайта
   │  по запросу строит ОДНУ таблицу релиза: серия × плеер → клетка
таблица релиза ── представления (чистые функции): диапазоны, разрешения, выбор лучшего, layout, coverage
   │  клетки заполняет
политика (policy.py) — единственное место попыток, пауз, пределов времени и числа запросов на хост
   │  вызывает
плееры (players/: vk, allvideo, vibix, kodik, cdnvideohub) — общий контракт
```

Файловая раскладка:

```
modules/sources/
├── policy.py                   попытки, паузы, предел времени, запросы на хост
├── players/
│   ├── contract.py             контракт плеера и виды ответа
│   ├── vk.py, vk_show.py       VK: поиск, прямой запрос, чистое чтение его ответа, прямая ссылка для загрузки
│   ├── allvideo.py             AllVideo
│   ├── vibix.py                Vibix: протокол, ключи, захват каталога
│   ├── kodik.py, cdnvideohub.py
└── video_providers/
    ├── base.py, registry.py, ranges.py
    ├── ruchime/                provider.py, site.py, table.py, views.py, address.py
    └── dunhuatv.py
```

Зависимости направлены вниз: `provider → table → policy → players`. Плеер не знает ни политики, ни парсера; политика знает только
контракт плеера; таблица не знает конкретных плееров.

Контракт плеера: `find(текст страницы)` — чистая функция; `fetch(ссылка)` — один запрос без повторов; `read(ответ)` — чистый разбор
в один вид (играет с разрешениями, не найдено, закрыто, не плеер, ошибка статуса); `resolve(ссылка)` — поток перед загрузкой.
Видов «неуверенно» нет: любой ответ относится ровно к одному виду.

Клетка таблицы: окончательный вид, разрешение, число попыток. Если попытки или время вышли, клетка — «не получено», а не «нет».

## Требования (жёсткие)

1. **Плеер — расширяемый список, а не две ветки в коде.** Провайдер читает
   `data-player`/`switchSource` со страницы и выбирает из зарегистрированных
   адаптеров; новый плеер добавляется одним адаптером, без правки логики выбора.
2. **Источник выбирается по факту доступности, а не по наличию кнопки.** Плеер,
   у которого нельзя получить поток, не должен попадать в кандидаты.
3. **Мёртвый источник не уходит в загрузку.** Эпизод без доступного плеера не
   становится кандидатом с заведомо нерабочей ссылкой.
4. **Ссылка, сохранённая в кандидате, разрешается в момент скачивания.** Как
   сейчас у AllVideo: в БД лежит ссылка плеера, поток получается перед
   загрузкой (`sources.video.stream`), потому что ссылки с подписью протухают.
5. **Доступность видна пользователю.** Система различает «серии на VK нет»,
   «серия на VK есть, но видео закрыто настройками приватности» и «серия есть,
   но не загружена».
6. **Парсер не должен разговаривать с сайтом дольше, чем нужно.** Разбор
   ссылки релиза — только страница релиза; постраничный обход серий — на скане,
   по всем сериям (источник может исчезнуть или сменить разрешение).
7. **Правила модулей не нарушаются.** Плееры — внутри модуля `sources`;
   протоколы внешних сервисов (Vibix/Kinescope) — в профильных файлах рядом с
   парсерами, без бизнес-логики в `gateway`.
8. **Эмпирика.** Поведение внешних плееров утверждается только после проверки на
   живых данных (страница серии, ответ API плеера, реальный поток).
9. **Источник выбирается по максимальному разрешению; при равенстве —
   приоритет VK → AllVideo → Vibix.** Плеер, не давший поток, в кандидаты не
   попадает. Kodik не используется — 720p недостаточно. Ранний выход: если все
   серии уже имеют 2160, нижние плееры не проверяются. Живой пример, почему
   приоритет не абсолютен: AllVideo на 386–387 отдаёт 360p, Vibix — 1080p;
   выбор строго по приоритету нарушил бы п. 10.
10. **Разрешение — всегда максимально доступное.** Появление более высокого
    разрешения у любого источника считается новым файлом: композиция
    перестраивается и докачивает лучшее качество. Речь только о разрешении.
11. **Доступность и качество проверяются фактической пробой:** автоскан,
    ручной скан, полный опрос в редакторе правил, добавление ссылки, ручное
    обновление композиции. Открытие композиции показывает последнее
    сохранённое состояние (автообновление web-серии выключено). Последнее
    состояние запоминается.
12. **Ключ расшифровки не зашивается в код.** Глобальный кэш с TTL 12 часов:
    по умолчанию последний полученный ключ, по истечении — перезапрос, при
    ошибке расшифровки — немедленный перезапрос.
13. **Качество — только факт.** Любая плашка разрешения выводится из
    фактической пробы серии; быстрый разбор релиза качество не подставляет.
14. **Разбор ответа — чистая функция.** Без сети, времени, состояния и повторов; определена для любого входа; каждый вход
    относится ровно к одному виду из закрытого набора. Проверяется на настоящих образцах каждого вида.
15. **Политика — в одном месте.** Повторы, паузы, предохранители времени и числа попыток, число одновременных запросов на хост
    реализованы один раз (`policy.py`); в плеерах и парсерах их нет.
16. **Один раз по запросу.** Страница серии читается один раз, плеер на серии пробуется один раз; пока таблица релиза
    собирается, остальные запросы шины ждут её завершения и сайт не читают. Готовая таблица живёт в памяти ограниченное время.
17. **Недоступные серии отражаются диапазонами** («1-4, 6-10») по каждому плееру; серии, для которых ответ не получен за
    отведённые попытки, считаются отдельно от серий, которых у плеера нет.
18. **Плееры общие.** VK, AllVideo, Vibix, Kodik и cdnvideohub реализуют один контракт; парсер сайта выбирает, какие использовать.

## Критерии успеха

- Серия «Практикуя ци сто тысяч лет» добавляется в загрузку: 387-я серия
  получает источник Vibix с максимально доступным разрешением (1080p по
  текущим данным), скачивается и появляется в медиатеке.
- Добавление серии в интерфейсе возвращает отчёт о плеерах: какие есть, какие
  доступны, с каким разрешением; для этой серии — «VK: закрыто настройками
  приватности».
- Плеер без источника не появляется в очереди скачивания.
- Разбор ссылки релиза (добавление серии) укладывается в единицы секунд при
  релизе на 387 серий.
- Регрессии нет: живая серия «Несравненный боевой дух» (34 серии, все с VK
  2160p) продолжает разбираться и качаться как раньше.

## Что переиспользуем (готовые кирпичи)

- `modules/sources/video_providers/` — точка расширения провайдеров.
- `modules/sources/module.py` — браузерный пул Playwright (для Vibix) и
  `sources.video.stream` — хук разрешения потока перед скачиванием.
- `modules/scan/planner.py` — планировщик уже умеет выбирать лучшего кандидата
  на серию из нескольких по приоритету качества.
- `modules/downloads/ytdlp.py` — скачивание: прямой HLS/mp4 через ffmpeg,
  VK — по embed-потоку; каноническая ссылка остаётся идентификатором.
- `media_items.is_available` — неиспользуемая колонка: естественное место для
  признака «источник недоступен».

## Рамки/запреты (выстраданные)

- **Обфускация Kinescope уже разобрана стендом** (`scripts/vibix_stand`,
  этап 5): ключ восстанавливается из зашифрованного манифеста и кэшируется;
  повторно «на коленке» ничего не расшифровываем.
- **Не подставлять ссылку, которую нельзя открыть.** «Ссылка есть на странице»
  не значит «видео доступно».
- **Не ломать обратную совместимость.** Ссылка VK-кандидата остаётся
  `https://vk.com/video<oid>_<id>` (от неё зависит идентификатор элемента
  медиатеки у уже заведённых серий).
- **Не трогать БД без нужды**; изменения схемы — отдельной миграцией с бэкапом.
- Дизайн и тексты интерфейса не меняются без отдельного согласования.

## Решения пользователя (обязательны)

1. **Kodik не используется:** 720p — неудовлетворительное разрешение. Остаются
   VK, AllVideo, Vibix.
2. **Приоритет источников:** VK, затем AllVideo, затем Vibix — как тай-брейк
   при равном разрешении. Выбор — по максимальному разрешению; если все серии
   уже имеют 2160, нижние плееры не сканируются.
3. **Разрешение:** всегда максимально доступное; более высокое разрешение —
   новый файл, композиция перестраивается и докачивает лучшее качество.
4. **Точки обновления:** автоскан, ручной скан, полный опрос в редакторе
   правил, добавление ссылки, ручное обновление композиции. Открытие
   композиции web-серии скан не запускает (автообновление выключено).
5. **Скан обходит все серии**, но исключённые правилами не опрашивает: сначала
   быстрый список `ALL_EPS`, затем правила, затем страницы только неисключённых.
6. **Тест правил — только факты:** полный опрос серий с качеством, даже если
   это занимает минуты.
7. **Браузер** — существующий пул модуля `sources`, без отдельного запуска.
8. **Ключ** — глобальный кэш с TTL 12 часов и автоматическим восстановлением
   (требование 12).
9. **Парсер сам собирает таблицу релиза один раз по запросу;** плееры вынесены в общие модули (требования 14–18).
10. **Один файл на эпизод — максимального разрешения.** Низкое качество,
   пришедшее первым, заменяется высоким: файл проигравшего удаляется после
   того, как файл победителя скачан (Р-37).
