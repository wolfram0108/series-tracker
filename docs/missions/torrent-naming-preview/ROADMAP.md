## РЕЗУЛЬТАТЫ СТЕНДА (2026-07-02, magnet→файлы, живой qBit v5.2.1)

Инструмент: `scratchpad/magnet_stand.py` (прод-`QbtClient` + реальные
anilibria-магниты из API `anilibria.top/api/v1`). Безопасность: работа только
со своим infohash, 14 прод-раздач под защитой, `delete` в `finally`.

- **paused-магнит метаданных НЕ качает** (3/3, 40с): state залипает `stoppedDL`,
  `total_size=-1`. У qBit нет нативного «metadata-only» — подтверждено.
- **STARTED-магнит: список файлов за ~0.5–2.5с** (11/11 попыток на 45–63 сидах),
  реальные имена (`...[01]_[HEVC].mkv`). На момент прихода метаданных
  **`downloaded=0 Б`** (метаданные приходят до пирсов) — контент не течёт.
- **Уборка чистая:** `delete(deleteFiles=true)` в `finally`; после всех прогонов
  в qBit ровно 14 прод-раздач, транзиентных 0.
- **Путь отказа:** dead-магнит (случайный infohash + реальные трекеры) — state
  `metaDL`, `torrent_files=[]`, грациозный таймаут, чистая уборка. Не виснет.
- Нюанс: часть раздач попадала в `queuedDL` (очередь qBit), но метаданные всё
  равно доезжали за ~1-2с. Под НАСЫЩЕННОЙ очередью не проверено (этап 2b).

Итог: механизм для прода — **add STARTED → poll `/torrents/files` (poll ~0.5с,
timeout ~20-30с) → прочитать имена → `delete(deleteFiles=true)`**. Best-effort:
нет сидов → грациозная деградация.

### Зомби-безопасность (2026-07-02, `scratchpad/zombie_safety*.py`)
- **Провал наивного подхода (ВАЖНО):** «add + однократный sweep по категории
  прямо сейчас» оставил зомби — add АСИНХРОННЫЙ, раздача не успевает попасть в
  список/категорию к моменту sweep; после снятия наблюдения осиротевшая
  started-раздача за секунды скачала **273 МБ**. Одноразовый sweep НЕ надёжен.
- **Надёжное решение (проверено, qBit остаётся 14):** две линии обороны —
  - RUNTIME (отмена/переоткрытие): `cleanup_confirmed(ih)` — бьём `delete` по
    ИЗВЕСТНОМУ infohash, пока qBit не подтвердит отсутствие. Убрал за 1.2с даже
    при отмене сразу после старта.
  - BACKSTOP (краш): preview-раздачи в выделенной категории `st-naming-preview`;
    осевшую раздачу sweep категории ловит (скачано 0 Б), после — категория пуста.
    Моделирует `torrents.on_start` reconcile.
- **Идемпотентность:** двойной add того же магнита = 1 раздача (дедуп qBit по
  infohash) → быстрые переоткрытия окна схлопываются сами.

### Ветка .torrent (2026-07-02, `scratchpad/torrent_files.py`, 32 реальных файла из `torrent_cache/`)
- **32/32 разобрано, 0 ошибок.** Список файлов достаётся поверх существующего
  `infohash.py::_decode` (~30 строк), локально, мгновенно, **qBit не нужен**.
- **Нюанс кодировки:** предпочитать ключи `name.utf-8`/`path.utf-8` (рус-трекеры
  кладут основной путь в cp1251; qBit отдаёт utf-8-вариант). С этим русские
  папки (`Американский папаша (22 сезон)`) декодируются верно → предпросмотр
  совпадёт с фактическим переименованием.
- Реальный разброс: 4–226 файлов на раздачу, вложенная папка + видео.
- **Находка, оправдывающая фичу:** в раздаче `Record.of.Mortals.Journey…` имена
  в САМОМ .torrent уже с `.mkv.mkv.mkv` — кривизна из источника; предпросмотр
  показал бы её до добавления.

## ТУПИКИ (НЕ повторять)

- **libtorrent** для magnet — отвергнут: новая тяжёлая C++-зависимость (в
  requirements НЕТ, в .venv не установлена, Python 3.12.3), дублирует роль qBit
  (Р-1), та же зависимость от swarm/BEP-9 — надёжнее qBit-добора не будет.
- **Внешние magnet→torrent сервисы** — отвергнуты (надёжность/приватность/внешняя завязка).
- **Имена файлов из самой magnet-ссылки** — невозможно: magnet несёт только
  `infohash` (+ `dn`/трекеры), без списка файлов. Подтверждено (BEP-9 metadata
  докачивается из swarm; `infohash.py:89-114`).
- **anilibria API как источник имён файлов** — НЕ даёт: отдаёт `magnet`/`hash`/
  `episodes`(«1-17»)/`quality`, но не имена файлов внутри раздачи
  (`modules/sources/anilibria.py:31-52`). Значит, добор метаданных всё равно нужен.
- **magnet, добавленный PAUSED** — метаданные не качает (проверено на стенде,
  3/3). Для добора нужно STARTED. НЕ закладывать paused-путь.

## УТОЧНЁННЫЙ ДИЗАЙН (со слов пользователя, 2026-07-02)

Добор — **автономный фоновый префетч**, не ручная кнопка: пользователь вставил
ссылку → парсинг вернул раздачи (все качества) → **сразу в фоне** стартует добор

выбранное качество. Фоновая задача обязана переживать отмену/быстрые переоткрытия
окна БЕЗ зомби в qBit — решение проверено (этап 2b).
