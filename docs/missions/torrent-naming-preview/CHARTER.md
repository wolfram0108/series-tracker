# CHARTER — Оценка нейминга при добавлении торрента

> Слой 1. Короткий, меняется редко. Читать ПЕРВЫМ. Прогресс — в ROADMAP.md.
> Старт 2026-07-02.

## Цель (одним абзацем)

При добавлении сериала пользователь сейчас **не может заранее оценить**,
распознает ли система нейминга имена файлов в добавляемой раздаче —
единственный способ увидеть работу правил находится в Настройках (тест в
разделе «Фильтры»). Цель миссии — принести этот предпросмотр **в окно
добавления сериала**: показать список файлов выбранной раздачи и то, как к
ним применятся правила нейминга (распознанные сезон/серия/качество и/или
итоговые имена), **ещё до реального добавления**.

## Целевой результат / архитектура

```
AddSeriesModal (окно добавления)
   └─ новая вкладка «Проверка нейминга» (переиспользует ParserTest.vue)
         │  источник имён = НЕ VK-скрейп и НЕ уже-заведённая серия,
         │  а СПИСОК ФАЙЛОВ выбранной раздачи, полученный на этапе добавления
         ▼
   Бэкенд: предпросмотр списка файлов раздачи
         ├─ .torrent  → локальный разбор bencode (расширить infohash.py) — без сети, без новых зависимостей
         └─ magnet    → добор метаданных через qBittorrent (add STARTED → poll files → read → delete) — best-effort
                        (paused НЕ качает метаданные — проверено на стенде; старт даёт список за ~1-2с при 0 Б контента)
         ▼
   Движок правил (rules.format_torrent_file / rules.test) → рендер результата
```

Отличие от текущего: сейчас предпросмотр правил живёт только в Настройках и
питается VK-скрейпом либо именами уже заведённой серии; станет — доступен в
момент добавления и питается реальным списком файлов раздачи (.torrent/magnet).

## Требования (жёсткие)

1. **Модульность (Р-1, Р-7).** Получение списка файлов — в модуле `torrents`
   (единственный собеседник qBittorrent; там же уже живёт bencode/infohash).
   `sources` отдаёт `.torrent` (уже есть `sources.torrent_file.get`).
   Оркестрация HTTP — в `gateway`, без бизнес-логики.
2. **Нулевые побочные эффекты при предпросмотре.** Разбор `.torrent` — чистый.
   qBit-добор magnet: раздача добавляется **STARTED** (paused метаданные не
   качает — проверено), список файлов доезжает за ~1-2с при **0 Б скачанного
   контента** (метаданные приходят до пирсов); гарантированная очистка
   `delete(deleteFiles=true)` в `finally`; **без запуска конвейера** (без
   `torrents.register`). Зомби-безопасность (проверено на стенде — наивный
   однократный sweep-по-категории ЛОВИТ не всё из-за гонки async-add: брошенная
   started-раздача за секунды скачала 273 МБ): **две линии обороны** —
   (1) RUNTIME-уборка по ИЗВЕСТНОМУ infohash с подтверждением-поллингом
   (`delete` повторяется, пока qBit не подтвердит отсутствие) — переживает
   отмену/переоткрытие; (2) BACKSTOP — все preview-раздачи в выделенной qBit-
   категории, `torrents.on_start` reconcile сметает категорию (краш между add и delete).
3. **Без новых тяжёлых зависимостей.** Список из `.torrent` — существующим
   bencode-декодером; метаданные magnet — через уже имеющийся qBit.
4. **Best-effort, деградация вместо падения.** Нет сидов/таймаут по magnet →
   понятное сообщение, окно добавления продолжает работать.
5. **Дизайн/UX неприкосновенны.** Переиспользуем `ParserTest.vue` и общий CSS,
   визуал не дублируем и не меняем без явной просьбы.
6. **Эмпирика.** Поведение qBittorrent по добору метаданных проверить на живом
   qBit стенда ДО того, как закладывать это в архитектуру. (Выполнено — стенд.)
7. **Автономность фоновой задачи.** Добор списков файлов — фоном и автоматически
   при парсинге ссылки (не ручная кнопка), для ВСЕХ качеств раздачи сразу;
   результат кэшируется по infohash. К моменту, когда пользователь дойдёт до
   вкладки проверки, списки уже готовы (без задержки). Задача переживает отмену
   пользователем и быстрые переоткрытия окна (single-flight по infohash, дедуп
   qBit) — без зомби-раздач.
8. Язык — русский; **никаких упоминаний ИИ** в коде/коммитах/артефактах.

## Критерии успеха (как поймём, что готово)

- Для `.torrent`-раздачи (kinozal/rutracker/astar/anilibria_tv) — список файлов
  появляется **мгновенно**, предпросмотр правил совпадает с тем, что даст
  реальное переименование.
- Для anilibria-магнита — список файлов доезжает через qBit (при наличии сидов)
  и прогоняется через правила; при отсутствии — понятная деградация.
- Судья — **глаза пользователя** в окне добавления + сверка предпросмотра с
  фактическим переименованием после реального добавления.

  `renaming.preview` (`renaming/module.py:67`).
- **Фронт** — `ParserTest.vue` (отделим, зависит только от `profileId`);
  паттерн табов в шапке модалки (`ModalShell` слот `header-extra`).

## Рамки/запреты (выстраданные)

- **НЕ добавлять libtorrent** — дублирует роль qBit (Р-1), та же зависимость от
  swarm (BEP-9), тяжёлая C++-сборка; выигрыша над qBit-добором нет. См. ROADMAP «тупики».
- **НЕ использовать внешние magnet→torrent сервисы** (надёжность/приватность).
- **НЕ трогать визуал/DOM/классы**; правки JS-слоя данных — только по согласию.
- Архитектурные/функциональные/UI-правки — **только после явного «да»** пользователя.
