## РАЗВЕДКА: track-muxer (исходники на хосте демона, 2026-10-28)

Доступ: SSH-алиас `track-muxer-root` на сервере (хост `192.168.1.177`, ключ
`~/.ssh/id_ed25519_tm`). Проект: `/home/user/track-muxer` (git, `src/track_muxer`),
демон запущен как `track-muxer serve --port 8787 --out <downloads>`. Чтение —
свободно, правки в проекте — только по согласованию.

| Что | Факт |
|---|---|
| Конвейер | загрузка озвучек с сайтов-витрин → нормализация → выравнивание (`conform`) → сборка MKV (`mux`) |
| Выравнивание | «зрение»: карта таймлайна по видеоряду — единственный источник структуры видео, вырез в озвучке становится тишиной; «слух»: выравнивание по звуку поверх (`band`, DSP, 48 полос); тишина озвучки заливается звуком референса последним проходом |
| Требование к входу | озвучка — файл с видеорядом того же материала, что референс. Озвучка от другого видео отсекается до обработки звука. Видеослой сам исправляет кроп, зум, анаморф, полосы, зеркало, телесин. Режим `audio` (озвучка без видео) запускает только слой звука, менее надёжен, не используется |
| Задача серии | `POST /conform/enqueue`: `ref`, `dubs[]`, `out_dir`, `cache_dir`, `keep_tmp`, `audio_method`, `drift_speed_pct`, `fill_silence`, `ref_atrack`, `dub_atracks[]`. Пути проверяются на файловой системе демона; `out_dir` не может совпадать с каталогом источника |
| Повторный запуск | признаки референса считаются один раз и лежат в `cache_dir`; озвучки, чей выход уже есть (`skip_existing`), пропускаются. Задача с тем же `out_dir` и `cache_dir` при `keep_tmp=true` досчитывает только новые озвучки без повторного декодирования референса. При `keep_tmp=false` кэш удаляется после серии |
| Выход озвучки | `out_dir/<имя файла озвучки>.flac` (FLAC 16 бит, 44,1 кГц); дорожка № N>0 одного файла — суффикс `__aN`; одноимённые файлы с разным расширением — суффикс расширения |
| Имя озвучки | третье поле имени файла `<плеер>__<язык>__<студия>__<качество>p.<расширение>` становится названием дорожки при сборке |
| Субтитры | текстовые дорожки рядом с файлом переносятся на шкалу референса |
| Результат | `DubResult`: `ok`, `audio_resid_ms`, `audio_coverage`, `audio_cuts`, `suspect`, `warnings`, `critical`, `error`; порог «не сошлось» — остаток больше ±80 мс |
| Очередь | хранится в `_conform.json` / `_mux.json` рядом с загрузками, переживает перезапуск; параллельность — настройка (на хосте 4); видео от 1080p декодируется на GPU (не более 2 сессий) |
| Сборка | `POST /mux/enqueue`, задача сезона: `aligned_root` (каталог с `epNN/_aligned/*.flac`), `containers_dir` (видеофайлы; номер серии берётся из имени: `S01E02`, `ep01`, ` - 01 `), `out_dir`, таблица дорожек. Видео копируется без перекодирования; озвучки — FLAC (копия, если уже FLAC) или AAC; субтитры, главы, вложения копируются. Выход: `out_dir/<имя контейнера>.mkv` |
| Ограничения сборки | `skip_existing`: готовый выход не пересобирается; выход не может совпадать с контейнером |
| Загрузка озвучек у демона | резолверы плееров `kodik`, `cvh`, `alloha`, `sibnet`, `aksor`: `open(вариант)` → `resolve(сессия, серия)` → ссылки по качеству + заголовки + User-Agent; затем `ffmpeg -c copy` с переподключением |
| Пути | глазами демона `/mnt/meganas/media/...`; на сервере то же хранилище — `/nas/...` |

Не проверено: поведение при десятках озвучек в одной задаче; отмена и
перезапуск демона во время задачи.

## РИСКИ ПРОЕКТИРОВАНИЯ

| Риск | Следствие | Решение |
|---|---|---|
| Озвучки одной серии — конкуренты в планировщике слота | Р-37 удалит файлы проигравших озвучек | озвучки хранятся отдельно от видео-кандидатов (CHARTER, «Рамки») |
| Озвучка скачивается с видеорядом, N серий × M озвучек | объём хранилища и время загрузки | циклы по сериям, ограничение числа серий в работе, удаление временных файлов после успеха |
| Нумерация серий источников расходится (сезоны, склейки) | озвучка выравнивается по чужой серии | сопоставление серий по номеру и длительности до постановки; расхождение — ошибка, а не выравнивание |
| Озвучка от другого видеоряда (другая версия, другой монтаж) | демон отсекает её до обработки звука (`critical` / `suspect`) | такая озвучка не попадает рядом с видео; причина видна в «Агентах» |
| Референс заменён более высоким разрешением | выравнивание устарело | этап 8 |
| Референс переименован (правила, ручное переприменение) | дорожки рядом остаются со старым именем и теряются | этап 8: переименование видео переименовывает дорожки |
| Plex не читает внешние аудиодорожки рядом с файлом | для Plex дорожки невидимы | этап 11 (упаковка); Jellyfin читает с версии 10.8 |
| Защита сайтов от небраузерных клиентов | `kodikplayer.com` и `yummyani.me` дают 403 или обрыв рукопожатия без подмены TLS-профиля | резолверы демона работают через `curl_cffi` (профиль Chrome); у нас запрос к iframe Kodik проходит |

## КИРПИЧИ

- Резолверы `kodik.py` и `cvh.py` в `track-muxer` (`src/track_muxer/players/`): готовый протокол,
  портируется на асинхронный клиент; интерфейс «открыть сеанс на озвучку → ссылки по качествам +
  заголовки + User-Agent».
- Адаптер каталога `sources/yummyanime.py` в `track-muxer` — образец разбора страницы тайтла в
  набор «плеер × озвучка × серии».
- Провайдеры веб-видео: `modules/sources/video_providers/` (реестр, база,
  `StreamUnavailable`, разрешение потока перед скачиванием).
- Протокол Kodik на Python (ROADMAP миссии `ruchime-players`): страница плеера
  → подписи → `POST /ftor` → ROT18 + base64 → HLS; серия выбирается параметрами
  `season` и `episode`.
- Планировщик слотов и замена низкого разрешения высоким: `plan_with_supersession`,
  `media_items.superseded_by`.
- Модуль `downloads`: скачивание через `ffmpeg` по HLS и `yt-dlp`.
- В демоне `track-muxer` уже есть игроки `kodik`, `cvh` (= `cdnvideohub`),
  `alloha`, `sibnet`, `aksor`; его загрузки озвучек лежат в
  `downloads/<проект>/epNN/<плеер>__rus__<студия>__<качество>p.*`.
