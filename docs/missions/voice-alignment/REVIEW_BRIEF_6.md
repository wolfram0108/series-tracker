# ТЗ на шестой круг внешнего ревью: многодорожечная обработка сериалов

Дата: 2026-10-30. Состояние: актуально. Заменяет: `REVIEW_BRIEF_5.md` (пятый круг); нормативная часть и фокус перенесены сюда с вердиктами пяти кругов.

## 1. Предмет и цель

**Система.** `series-tracker` — медиа-сервер отслеживания, загрузки и нарезки сериалов. Один процесс `asyncio`: «тупая» шина (публикация и подписка с масками) и модули, общающиеся конвертами (событие, команда, запрос, ответ). Единственная HTTP/SSE-точка — модуль `gateway`; фронтенд — Vue 3 + TypeScript + PrimeVue.

**Предмет.** Возможность «сериал с несколькими озвучками»: сайт-витрина (`dunhuatv.ru`, плееры CVH и Kodik) отдаёт серию в нескольких озвучках; референс-озвучка остаётся в медиатеке, остальные скачиваются во временный каталог, выравниваются по референсу внешним сервисом выравнивания (HTTP/SSE-демон) и кладутся рядом с видео как внешние аудиодорожки в именовании Jellyfin. Состояние каждой озвучки видно в карточке серии.

**Первые пять кругов.** Первый круг (`ec23a2d^..8f00473`) дал 11 находок (S1–S3). Второй (`ec23a2d^..95d1f8f`) признал их закрытыми частично и нашёл 8 новых (N1–N8). Третий закрыл N3–N7 и нашёл пять (M1–M5). Четвёртый закрыл M2 и M5 и нашёл F1–F5. Пятый (код до `e063fee`, снимок `fd06cbb`) подтвердил исправление исходных сценариев F1–F5, закрыл F3, F4 и F5, признал F1 и F2 закрытыми частично и нашёл три дефекта владения ресурсами — G1 (S1), G2 (S1) и G3 (S2) — и пробел покрытия: удаление проверки элементов списка задач штатные тесты пропускали. Вердикт пятого круга: устойчивость этапов 6–8 принимать нельзя.

**Цель шестого круга.**

1. По каждой из находок G1–G3 и пробелу покрытия F3 установить, закрыт ли **класс** дефекта, а не только названное место, и проверить закрытие мутацией (убрать исправление — тест должен падать).
2. Установить статус остатков, названных в пятом круге (раздел 4.2: F1, F2, N1, остаток 4 и оценки компромиссов K32, K34).
3. Найти дефекты, внесённые исправлениями пятого круга (раздел 5).
4. Пересмотреть вердикты A, B, Q (разделы 6 и 7) и оценить вопросы к замыслу и компромиссы (разделы 9 и 10).

#### G1 (S1). Очистка родительского каталога игнорировала владение незавершённой задачи

| Поле | Содержание |
|---|---|
| Класс | удаление дерева без учёта всех владельцев вложенных ресурсов |
| Решение | единая проверка `_contested` (применяется ко всякому удалению из журнала — файлу, дорожке, дереву): путь пересекается с папкой идущей задачи живой строки (`aligning` с `out_dir`) или с папкой (`voice_cleanup.scope`) записи журнала о задаче либо отправке, не подтверждённой остановленной; пересечение — то же место, вложенное и вышестоящее (`_overlap`). | Носители | перечень отчёта: `_clear`, `_written_to` (замещён `_contested`), `_drop_orphans`, `_tidy`, очистка каталога эпизода при остающейся старой задаче; найденные: очистка папки серии при удалении сериала, выход озвучки из плана |

| Остаток | обязательство ожидания хранится так же, как остальные (в памяти, заново по БД при старте); пока остановка не подтверждена, не уходит и вышестоящая папка (K32) |

#### G2 (S1). Старый проход очистки завершал новую запись журнала для того же имени

| Поле | Содержание |
|---|---|
| Класс | завершение операции по имени ресурса без идентичности поколения |
| Решение | запись несёт версию (`voice_cleanup.version`, миграция `0024`); передача (`_UPSERT`: сброс строки, удаление эпизода, завершение эпизода, `journal_cleanup`) поднимает версию; запись кончается `cleanup_done(путь, версия)` — условным удалением прочитанной версии; неудачная попытка версию не меняет (`note_cleanup_error`). Все места завершения — удаление, имя занято новой озвучкой, остановка задачи — идут через `_finish`; если версия изменилась, проход возвращает «не закончено», и запись ведёт новый проход |

| Проверка | `test_a_pass_that_removed_the_old_file_does_not_end_the_entry_of_its_new_owner` (приостановка между удалением и завершением, как в отчёте), `test_an_entry_is_ended_only_in_the_version_that_was_read` |

| Поле | Содержание |
|---|---|
| Класс | проверка текущего отсутствия принимается за завершение ещё действующего производителя |

## 5. Поверхности риска исправлений

Исправления написаны одним автором и проверены его тестами. Искать в первую очередь:

| Код | Где | Что проверить |
|---|---|---|
| R1 | `_contested`, `_overlap`, `_clear` | пересечения, не учтённые проверкой (папка кэша, входные файлы, папка серии с другим регистром или с лишним разделителем); вечное ожидание записи, когда задача не подтверждается; два пересекающихся владельца, ждущих друг друга |
| R2 | `repository._UPSERT`, `cleanup_done`, `note_cleanup_error`, `_finish`, `_hand_over` | версия при записи несколькими строками одного оператора; обновления, поднимающие версию, когда не должны, и наоборот; места, где запись кончается не через `_finish` |
| R3 | `_stop_job`: порядок «журнал папки → конец записи → уборка папки», `poke("cleanup:")` | потеря записи о папке при обрыве между шагами; будящие вызовы из чужих контекстов |
| R4 | `_submit`, `_send`, `_sending`, `poke("cleanup:")`, `poke("submission:")` | ключ, оставшийся в `_sending` при исключении; отправки, чей исход не разобран долго; гонка разбора ответа с удалением сериала |
| R5 | `_attach(…, scope)`, `_cancel_job` | отмена задачи, чьи озвучки только что исчезли; повторная отмена той же задачи записью об отправке; обработка раннего окончания (`_unclaimed`) для ушедших озвучек |
| R6 | `_work_off` и снятие обхода журнала в конце `_advance` | записи, у которых нет обязательства восстановления; записи, оставленные состоянием «передана» после сбоя между шагами; прежнее поведение, на которое могли рассчитывать тесты и потребители |
| R7 | `_recover_one` (ветка без ожидающих строк) | задачи, оставшиеся без владельца, когда записи об отправке нет |
| R8 | миграция `0024` | обратный ход (`DROP COLUMN`), применение к БД с записями журнала |

| K31 | Папки поколений (`<результат>/<ключ>`, `<кэш>/<ключ>`) создаёт приложение до отправки; что демон пишет во вложенные папки с правами, созданными приложением, вживую не проверено (K14); остатки папок прежних поколений убираются вместе с папкой эпизода или после подтверждённой остановки задачи |

| K34 | Операция (`_follow`, `_drop_orphans`, `_tidy`, `on_series_deleted`, `_dispatch`) выполняет и ждёт только записи журнала, которые только что передала (в том числе свежие чужие); прежние записи ведёт исполнитель восстановления, конец прохода по серии журнал целиком не обходит; запрос моста к недоступному демону занимает до десяти секунд |
| K35 | Ключи отправок в пути (`_sending`) хранятся в памяти: после перезапуска модуля ни одного запроса в пути нет, а запись об отправке без ответа спрашивает сервис по ключу; запрос, дошедший до сервиса позже окна ответа моста, защитой не покрыт |
| K36 | Выход озвучки из плана (`drop_unplanned`) передаёт журналу и `output_path` строки со статусом `failed`: дорожка рядом с видео, на которую такая строка ещё указывает, будет удалена |
