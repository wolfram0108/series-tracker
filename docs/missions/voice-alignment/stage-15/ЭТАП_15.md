# Этап 15 — источник торрент: требования

Состояние: принято, 2026-11-16. Устройство — [DESIGN.md](DESIGN.md).

## 1. Цель

| № | Требование |
|---|---|
| 1.1 | Торрент-раздача — источник сериала наравне с остальными: равный участник выхода (РЕФ, озвучки, субтитры) |
| 1.2 | Путь один для всех источников: таблица строк → конструктор правил → «Выход» → планировщик |
| 1.3 | Разрешение, имена файлов, состав дорожек раздачи известны только после загрузки; описание раздачи на сайте — не источник данных о файлах |

## 2. Сайты

| № | Требование |
|---|---|
| 2.1 | В этап входит перенос существующих торрент-сайтов: kinozal, rutracker, anilibria, astar, anilibria_tv; новые сайты (nyaa) — позже |
| 2.2 | kinozal, rutracker: одна раздача, обновляется внутри себя |
| 2.3 | anistar: как сайты — одно видео, одна дорожка |
| 2.4 | anilibria: в разбор поступает одна раздача выбранного качества и обновляется |
| 2.5 | Раздача только с magnet — нынешним алгоритмом получения метаданных |
| 2.6 | Существующие торрент-сериалы не переносятся: удаляются |

## 3. Загрузка и синхронизация

| № | Требование |
|---|---|
| 3.1 | Источник добавляется как сайт; загрузка раздачи начинается кнопкой в окне сериала, не синхронизацией |
| 3.2 | Раздача качается в промежуточный каталог, не в каталог выходных файлов; путь каталога — в настройках; очередь и число одновременных загрузок — параметры qBittorrent, не приложения |
| 3.3 | Пока раздача не скачана полностью и не распознана, источника в сериале нет; синхронизация остальных источников идёт как обычно |
| 3.4 | Синхронизация берёт раздачу только загруженной и распознанной, в состоянии на момент своего начала |
| 3.5 | Во время синхронизации раздача не обновляется |
| 3.6 | Обновление раздачи независимо от синхронизации: сайт опрашивается по дате раздачи; дата изменилась — новый `.torrent` заменяет прежний; прежние файлы опознаются, качаются только новые |
| 3.7 | На время обновления раздача недоступна: РЕФ из неё недоступен — берётся запасной по порядку РЕФ, без запасного — «нет референса» |
| 3.8 | Тождество файла между версиями — путь в раздаче; переименованный файл — новый файл |
| 3.9 | Видеодорожка файла для одного источника всегда считается неизменной |
| 3.10 | Управление раздачей в qBittorrent переносится бережно: получение метаданных (из `.torrent` и из magnet), переименование файлов внутри qBittorrent, смена путей; каждая обязанность нынешнего модуля `torrents` получает место в новой модели или явное решение об удалении |

## 4. Хранение

| № | Требование |
|---|---|
| 4.1 | Дублирование файлов недопустимо; единственное исключение — промежуточные файлы следимой раздачи рядом с выходными файлами |
| 4.2 | Следимая раздача (автообновление включено): промежуточные файлы хранятся до конца обновлений |
| 4.3 | Выключение автообновления удаляет промежуточные файлы; остаются выходные файлы библиотеки |
| 4.4 | Архивная раздача (сырьё и РЕФ): после полной загрузки и первой сборки промежуточные файлы не хранятся |
| 4.5 | Торрент ненадёжен: раздача может стать недоступной полностью; после удаления промежуточных файлов единственная копия собранного — библиотека |
| 4.6 | Видео торрента живёт в библиотеке, пока оно РЕФ: к нему выравниваются новые озвучки; при другом РЕФ оно затирается, офлайн-озвучки выравниваются по новому РЕФ; вернуться к прежнему видео — скачать заново |

## 5. Редактор торрента

| № | Требование |
|---|---|
| 5.1 | Четыре вкладки: «Файлы», «Озвучки», «Субтитры» — файловая стадия; «Контейнеры» — после загрузки |
| 5.2 | Каждая вкладка: слева — исходные элементы, сверху — конструктор правил вкладки, справа — выходная раскладка (чистовик) |
| 5.3 | Все назначения для пользователя — каталоги справа: сезоны и серии, озвучки, субтитры. На каждой вкладке каталог создаётся, называется, и в него перетаскиваются элементы слева |
| 5.4 | Имя каталога озвучки или субтитров — название, которое приходит в строке в конструктор правил сериала (каталог «ДБ-Анилибрия» → озвучка «ДБ-Анилибрия») |
| 5.5 | «Файлы»: слева — дерево файлов раздачи; файл, которому правила дали сезон и серию, — зелёный, без них — красный. Справа — чистовик «сезон → серия»; кнопки «Создать сезон», внутри сезона «Создать серию» — пустые заготовки; файлы, которые правила не разложили, перетаскиваются в серии и сезоны |
| 5.6 | Номер серии и сезона по названиям файлов даёт выделенный пресет конструктора правил — один на все торренты, нужен только редактору; профили сериалов создаются как обычно |
| 5.7 | «Озвучки»: слева — звуковые файлы чистовика вкладки «Файлы»; сверху — правила озвучек; справа — каталоги озвучек с названием и языком |
| 5.8 | «Субтитры»: так же для субтитров — название, язык, тип (полные, надписи). Как субтитры лягут в выходной контейнер (по умолчанию, форсированные), решается на «Выходе», не в торренте |
| 5.9 | «Контейнеры»: раскладка контейнеров; контейнеры с одинаковым составом дорожек схлопываются в один; правила сверху назначают дорожкам озвучки и субтитры |
| 5.10 | Название и язык дорожки внутри контейнера берутся из метаданных; нет их — дорожку назначает правило или оператор; автоматики и эвристики нет |
| 5.11 | Ручное перетаскивание действует только на перетащенные файлы и на новые файлы не переносится; правила при обновлении раздачи назначают новые файлы сами |
| 5.12 | Внешний звук без видео в раздаче не обрабатывается |
| 5.13 | Экран редактора — по принятому макету (2026-11-17): вкладка «Торрент» окна сериала; правила — карточки-таблицы конструктора правил приложения («ЕСЛИ / ТО», палитра блоков, поля строки) |

## 6. Строки и выход

| № | Требование |
|---|---|
| 6.1 | Каждая дорожка — отдельная строка таблицы с видео своего файла |
| 6.2 | В «Выходе» дорожки разобранного файла — многодорожечного или с дорожками в каталогах — выглядят и управляются как строки сайтов: смена, перестановка, отключение |
| 6.3 | Многодорожечный исходный файл управляется как выходной: видны дорожки, выходной файл собирается по плану |
| 6.4 | Файл раздачи с несколькими сериями — компиляция по общим правилам: номера диапазона даёт конструктор правил, РЕФом серий она становится только разбором по шкале одиночной серии или эталона разметки |

## 7. Синхронность и конформ

| № | Требование |
|---|---|
| 7.1 | Внутренние и внешние дорожки раздачи полностью синхронны видео раздачи своей серии |
| 7.2 | РЕФ — видео этой раздачи: дорожки раздачи берутся без конформа |
| 7.3 | РЕФ — другое видео: дорожки раздачи проходят конформ; видеочастью внешней дорожки служит видео раздачи этой серии |

## 8. Субтитры

| № | Требование |
|---|---|
| 8.1 | Субтитры — дорожки наравне со звуком; переносятся любые: текстовые, картинные, ASS целиком |
| 8.2 | Управление как у звука: включение, отключение, порядок |
| 8.3 | Порядок субтитров — одна таблица на серию и одна на сериал, не по озвучкам |
| 8.4 | Упаковка субтитров в выходной файл — приложение; перенос времени субтитров к чужому РЕФ — демон выравнивания ([TRACK_MUXER_SUBTITLES_CHAPTERS.md](TRACK_MUXER_SUBTITLES_CHAPTERS.md)) |

## 9. Главы

| № | Требование |
|---|---|
| 9.1 | Главы переносятся в выходной файл |
| 9.2 | Главы источника, выровненного к РЕФ, переносятся на шкалу РЕФ демоном выравнивания при конформе ([TRACK_MUXER_SUBTITLES_CHAPTERS.md](TRACK_MUXER_SUBTITLES_CHAPTERS.md)) |
| 9.3 | Главы РЕФ всегда в приоритете; перенесённые главы выровненного источника берутся, только когда у РЕФ глав нет |
