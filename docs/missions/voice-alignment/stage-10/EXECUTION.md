# Этап 10 — план исполнения

> Дата: 2026-11-01. Состояние: действует. Жанр — план работ с журналом состояния.
> Что делается — `SPEC.md` и `ARCHITECTURE.md`; что перестраивается — `REVISION.md`; чем доказывается — `VERIFICATION.md`.
> Этап выполняется одним заходом (`DECISIONS.md`, Д-26): пакеты ниже сходятся в одну систему, промежуточных состояний
> «приложение работает» не заводится; зелёными по ходу остаются тесты затронутого пакета и тесты нетронутых модулей.

## 1. Правила исполнения

| Правило | Содержание |
|---|---|
| Исполнитель пакета | субагент модели Sonnet с явным заданием; не больше трёх одновременно; законы называются в задании прямой строкой: `law-arch`, `law-run`, `law-measure`, `refactoring-methodology`, `law-docs`, `claim-integrity-gate`, `invariant-first-design`; для интерфейса — `law-ui` |
| Владение файлами | у каждого файла в одно время один пишущий; пакет трогает только свои файлы из таблицы 3; общие файлы (`tests/conftest.py`, `run.py`, `gateway/module.py::SSE_MAP`, `contracts/bus_topics.md`) правит указанный в таблице владелец |
| Контракты | `core/contracts/*` пишет и меняет только руководитель исполнения; исполнитель, которому контракт тесен, сообщает об этом в отчёте, а не правит его |
| Прогоны | через `progon_runner.py exec` с предикатом и предохранителем не больше 180 с; исполнитель гоняет только тесты своего пакета; полный набор гоняет руководитель |
| Старое и новое | точка со статусом «удалена» удаляется в своём пакете вместе с вызовами и тестами; параллельной жизни старого и нового нет; строка `REVISION.md` получает отметку «сделано» |
| Тесты | поведение, подтверждённое `REVISION.md`, остаётся и переносится на новый вход; тест, проверявший удалённое, удаляется; разбор сайтов проверяется на снятом сырье `raw/` (нет образца — «нет образца <файл>») |
| Код | комментарии на английском, 1–2 строки, «почему»; тексты интерфейса ключами; пауз и опроса между модулями нет; у каждой асинхронной операции сигналы успеха и провала |
| Готов пакет | `py_compile`; тесты пакета зелёные по предикату; строки `REVISION.md` пакета отмечены; отчёт: сделано, не сделано, хвосты, список изменённых файлов |
| Коммиты | исполнитель не коммитит: параллельные пакеты делят один индекс; руководитель принимает отчёт, проверяет и коммитит файлы пакета на русском без атрибуции ИИ |
| Отчёт исполнителя | по ступеням: отчитался — получил следующую; хвост из отчёта досылается тому же исполнителю |

## 2. Сквозные решения исполнения

| № | Решение | Следует из |
|---|---|---|
| Ис-1 | `catalog.series.get` и `.list` отдают `kind` (`torrent` или `video`) и `sources` (источники сериала со всеми полями). Колонки `url`, `source_type`, `parser_profile_id`, `vk_search_mode`, `vk_quality_priority` у сериала исчезают. Поля источника: `id`, `series_id`, `position`, `url`, `source_type` (`torrent`, `vk_video`, `web_video`), `parser_profile_id`, `vk_search_mode`, `vibix_season`, `players_off` | Д-38, Д-35, `REVISION.md`, 9.3 |
| Ис-2 | Номера миграций закреплены: 0025 — `catalog`, 0026 — `sources`, 0027 — `composition`, 0028 — `scan`, 0029 — `voices`. Пустые ревизии созданы заранее; пакет наполняет только свою | `ARCHITECTURE.md`, раздел 8 |
| Ис-3 | `tests/series_factory.py` — единственное место, где тесты создают сериал с источниками; пишет пакет П-1, остальные берут из него | Т-34 |
| Ис-4 | Исключение пробы плеера — «не получено» с причиной, не «нет» | Т-5 |
| Ис-5 | Запасной путь yt-dlp решается по плееру кандидата, не по виду сериала | `REVISION.md`, 9.3 |
| Ис-6 | Метка плеера для строки для конструктора приходит полем строки таблицы `player_label` из плеера; в `core` карты плееров нет | Т-42 |
| Ис-7 | Профиль конструктора передаётся параметром запроса (`profile_id`); модуль `rules` таблиц других модулей не читает | Т-34, `REVISION.md`, 9.2 |
| Ис-8 | Строка, исключённая конструктором (`exclusion: rule`) или оставшаяся без номера серии (`exclusion: no_number`), хранится в раскладке с признаком, но `composition.get` отдаёт её только по запросу `include_excluded`; потребители раскладки таких строк не видят | З-3, Д-8 |
| Ис-9 | Запросы `catalog.sources.add`, `.update`, `.remove` отвечают результатом (идентификатор источника или отказ с причиной): вызывающему нужен ответ. Удалить единственный источник сериала нельзя (`last_source`) | `ARCHITECTURE.md`, 5.1 |
| Ис-10 | Часть 1: одиночная строка без части в слоте, где части есть, получает часть 1; слот — источник, плеер, имя озвучки, сезон, серия; считает только `composition/project.py` | `REVISION.md`, раздел 4 |
| Ис-11 | Удаление `core/contracts/release.py` и `Layout` из `voices.py` делает руководитель после закрытия П-3 и П-5: контракты правит он один | З-5, раздел 1 |
