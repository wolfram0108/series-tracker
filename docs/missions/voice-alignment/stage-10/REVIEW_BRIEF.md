# ТЗ на независимое ревью этапа 10: сериал с несколькими источниками

Дата: 2026-11-02. Состояние: актуален. Первый круг ревью этапа; предыдущие брифы миссии (`../REVIEW_BRIEF*.md`) относятся к этапам 0–9.

## 1. Предмет и цель

**Система.** `series-tracker` — медиа-сервер отслеживания, загрузки и обработки сериалов. Один процесс `asyncio`: «тупая» шина (публикация и подписка с масками) и модули `modules/*`, общающиеся конвертами (событие, команда, запрос, ответ); запрос-ответ реализован в обвязке `core/module.py` поверх шины. Шлюз `modules/gateway` — единственная точка HTTP и SSE. База данных — приватная память модуля-владельца. Интерфейс — `web/src` (Vue 3, TypeScript, PrimeVue).

**Предмет.** Этап 10 миссии `voice-alignment`: сериал с несколькими источниками (страницы сайтов `1.ruchime.org`, `dunhuatv.ru`, канал VK с запросом).

| Узел | Что стало |
|---|---|
| Источники | у сериала один и более источников; вид сериала (`torrent` или `video`) определяется источниками, смешение запрещено |
| Таблица страницы | страница читается одним процессом, один раз в час; таблица хранится в БД, публикуется только полной; её читают все потребители (окно добавления, окно сериала, тест правил, скан, озвучки) |
| Конструктор правил | номер серии, сезон, диапазон и часть возникают только как ответ конструктора на строку источника; блок «диапазон» фильтрует строки |
| Раскладка | модуль `composition`: строки всех источников с номерами, группы озвучек (только пользовательские), «Неизвестная озвучка N», рычаги трёх уровней (сериал, сезон, серия) с наследованием |
| Референс | модуль `scan`: одиночная серия наибольшего разрешения, при равном — плеер выше в приоритете; ручной выбор рычагом; отметки `by_level`, `own`, `other_player`, `none`, `unfit`, `off` |
| Отключение | серия и сезон отключаются одной командой `scan.output.switch`; отключённая серия остаётся в выходе с отметкой `off` |
| Озвучки | модуль `voices` строит план из раскладки и референсов, качает не выше 720p, отправляет в сервис выравнивания, кладёт дорожки рядом с референсом; вердикт пары — `ok` сервиса |
| Интерфейс | редактор источников (одно окно добавления и свойств), раздел «Выход» вместо вкладки «Композиция» у видео-сериалов, тест профиля по таблице страницы или списку названий, кнопка «Перечитать» |
| Данные | миграции `0025`–`0031`; удалены `video_availability`, `site_episode`, `preferred_voiceovers`, прежние `Layout` и `Release` |

## 4. Карта устройства

Таблицы и их владельцы (единственный модуль, чей SQL называет таблицу; закреплено сторожем `table_owners`):

| Модуль | Таблицы этапа | Роль |
|---|---|---|
| `catalog` | `series`, `series_sources` | сериалы, источники сериала, вид сериала, каскад удаления |
| `sources` | `release_tables`, `release_rows`, `trackers` | чтение страниц сайтов, плееры, таблица страницы, срок часа, одно чтение страницы за раз |
| `rules` | `parser_profiles`, `parser_rules`, `parser_rule_conditions` | конструктор правил: ответ по ключу строки, тест профиля |
| `composition` | `composition_state`, `composition_sources`, `composition_rows`, `unknown_voices`, `output_settings` | раскладка из таблиц, профилей и групп озвучек; рычаги выхода; предпросмотр для окон до создания сериала |
| `scan` | `media_items` (строки), `scan_tasks`, `scan_references` | план серий, референсы, раздел «Выход» (`output.py`), отключение, синхронизация |
| `voices` | `voice_dubs`, `voice_files`, `voice_cleanup`, `voice_epoch` | план озвучек, загрузка, очередь выравнивания, дорожки, уборка |
| `downloads`, `conform`, `renaming`, `library`, `slicing`, `torrents` | свои | загрузка (yt-dlp), сервис выравнивания, имена файлов, перенос в медиатеку, нарезка (код этапом не тронут), раздачи qBittorrent |
| `gateway` | — | HTTP и SSE: запрос → запрос или команда шины; событие шины → SSE по таблице `SSE_MAP` |

Колонки таблицы `media_items` принадлежат разным модулям (`scan`: строка плана; `downloads`: `status`, `final_filename`; `slicing`: колонки нарезки); исключения из сторожей перечислены в самих сторожах с обоснованием (`PLAN_READERS`, `DYNAMIC_ALLOWED`, `DYNAMIC_COLUMNS_ALLOWED`) и входят в предмет ревью (раздел 8).

Основной поток:

```
sources.table.* ─► rules (ответ по ключу) ─► composition (раскладка, группы озвучек, рычаги)
        ▲                                          │ composition.changed
        │ чтение раз в час                          ▼
   страница сайта                       scan (референс, план, выход) ─► downloads ─► voices ─► conform ─► library
                                                   │ scan.reference.changed        voice_dub_update
                                                   ▼
                                       gateway: SSE (reference_changed, composition_changed, …) ─► web/src
```

Запуск процесса — `run.py`; порядок старта модулей фиксирован; сигнал `system.started` публикуется после старта всех модулей, и работа, требующая соседей (`voices`: допуск файлов, уборка, обязательства, очередь), стартует по нему, а не в `on_start`. Карта топиков — `contracts/bus_topics.md` (раздел «Что ушло в этапе 10» перечисляет удалённое).

## 9. Вопросы к замыслу

Решения, в которых автор не уверен и которые ревьюер оценивает по существу, а не только на соответствие ТЗ.

1. **Два механизма «отключено».** Серия отключается и как память сериала (`ignored`), и как строка плана; `off` не хранится, а вычисляется при чтении (`modules/scan/output.py: shown`, `switched_off`). Нет ли способа получить рассогласование, и достаточно ли это одного источника истины.
2. **Отметка `off` как значение `ReferenceMark`.** Отключение — свойство пользователя, а не результата выбора референса; верно ли помещать его в ту же перечислимость.
3. **«Таблица только полная».** Пока страница не прочитана целиком, потребители видят прежнюю таблицу или никакую; нет ли сценария, в котором большая страница (около 217 строк у ruchime, 236 с чтения трёх источников) блокирует сериал, или ошибка плеера на одной серии обесценивает всю таблицу (Т-5, состояние «не получено»).
4. **Порядок запуска и `system.started`.** Работа `voices` перенесена с `on_start` на сигнал после старта всех модулей. Любой модуль, чей `on_start` обращается к соседям запросом, — тот же класс дефекта: проверить каждый. Что видит интерфейс между подъёмом шлюза и сигналом.
5. **Вердикт пары — только `ok`.** Достаточно ли этого, если сервис вернул файл с `suspect` по 79–82 % кадров: что пользователь узнаёт о качестве результата, где видит сообщения сервиса.
6. **«Неизвестная озвучка N».** Нумерация должна быть стабильна при перечтении таблиц и изменении групп; рычаг `voice.take` по цели `group:<имя>` для неизвестных озвучек — на какой ключ опирается и переживает ли он пересчёт нумерации.
7. **Составное имя «A / B».** Одно имя, не делится; приемлемо ли это, когда сайт отдаёт озвучку как «A / B» и «B / A» (порядок).
8. **Единица счёта и ключ строки.** `row_key` и `source_id` в `media_items`, ключ строки конструктора, ключ рычага: стабильны ли ключи при перечтении страницы, смене профиля, удалении источника.
9. **Расширяемость.** Т-42 заявляет регистрацию в узле без правки соседей: подтвердить подсчётом мест правки для каждой из пяти сущностей (сайт, плеер, рычаг, правило референса, потребитель раскладки).
10. **Конструктор правил.** Условие `range` истинно, если число (или диапазон склейки вокруг него) пересекается с интервалом: нет ли расхождения этой семантики между Python и TypeScript и между тестом профиля и боевой раскладкой.
11. **Повторы и сетевые отказы.** Политика повторов (`core/retry.py`), предохранители и таймауты чтения сайтов, плееров, загрузки; все ли блокирующие вызовы имеют предел.
12. **Размер этапа.** 58 коммитов, около 34 000 добавленных строк: нет ли внутри несвязанных изменений, которые следовало отделить, и нет ли чрезмерной сложности относительно задачи.

## 10. Формат результата

**Находка** — отдельный блок:

| Поле | Содержание |
|---|---|
| № и тяжесть | `Н-1`, …; **S1** — потеря или порча данных, падение системы, нарушение закона этапа; **S2** — неверное поведение в штатном сценарии, нарушение требования ТЗ; **S3** — неверное поведение на краю, дефект проверок или документов; **S4** — замечание по форме |
| Происхождение | внесена этапом / существовала до этапа и не затронута / внесена исправлением предыдущей находки |
| Место | `файл:строка` (все носители) |
| Описание | одно-два предложения: что неверно |
| Доказательство | вывод команды, цитата кода, воспроизведение; без доказательства находка не принимается |
| Нарушенное требование | З-, Т-, И-, С-, Д-, Р- или правило Q |
| Класс и носители | к какому классу дефектов относится; перечень всех мест этого класса в коде, а не одно найденное |
| Предложение | исправление класса, а не места; если исправление меняет замысел — сказать об этом |

**Отчёт** состоит из:

1. Вердикт по каждому измерению Q-1…Q-14 («хорошо» / «частично» / «плохо») с обоснованием.
2. Сводка по группам A, B, C, Q: сколько требований соответствует / частично / не соответствует; список неисполненных поимённо.
3. Перечень находок, по убыванию тяжести.
4. Оценка компромиссов K-1…K-11 (раздел 8) и ответы на вопросы 1–12 (раздел 9).
5. Список проверенного и список **непроверенного** (чего ревьюер сделать не смог, почему).
6. Итоговая оценка качества: **готова к выкатке** / **готова после исправления блокеров** (перечислить) / **не готова** (причины), с двумя-тремя абзацами обоснования и оценкой по шкале 1–10.
7. Чем ревьюер проверял: команды и их вывод для каждого числа в отчёте.

Ревьюер не правит код и документы. Находка, с которой нельзя определить класс, помечается «класс не установлен» и сопровождается тем, что нужно проверить.

## 11. Вне области

- Старый фронт `legacy_frontend/`, вкладка «Нарезка» и модуль `slicing` (Д-34), торрентная композиция.
- Внешние системы как таковые: qBittorrent, сервис выравнивания, TMDB, сайты; предмет ревью — обращение к ним, а не их устройство.
- Оформление экрана «Выход» (Д-42: прорабатывается отдельно); оценивается наличие управления, а не вид.
- Внешний вид существующих экранов; оценивается лишь отсутствие регрессий.
- Развёртывание на сервер (бэкап БД, применение миграций, рестарт) — не выполнено; оценивается готовность к нему, не само действие.
- Запуск приборов `tools/collectors/*` на живых сайтах: требует доступа, учётных данных и разрешений владельца.
