# Этап 10 — ТЗ: сериал с несколькими источниками

> Дата: 2026-11-01. Состояние: проект, не утверждён; открытые пункты — `../ROADMAP.md`, раздел «Открытые вопросы».
> Первоисточник требований — текст владельца `ЭТАП_10.md` (эта папка) и решения `DECISIONS.md`. При расхождении
> этого документа с первоисточником прав первоисточник.
> Связанные документы: архитектура — `ARCHITECTURE.md`, ревизия старого кода — `REVISION.md`, инварианты — `LIFECYCLE.md`,
> проверка — `VERIFICATION.md`.

## 1. Цели

| № | Цель |
|---|---|
| Ц-1 | Каждая серия сериала берётся из набора источников в максимально доступном разрешении и кладётся в медиатеку |
| Ц-2 | Все доступные озвучки этой серии из всех источников кладутся рядом с ней в медиатеке, синхронными ей |

## 2. Рамки

| Входит | Не входит |
|---|---|
| Источники: канал VK (канал и запрос), `1.ruchime.org`, `dunhuatv.ru` | Торрент-сериалы: содержимое раздачи не разобрано до серий; их путь не меняется |
| Несколько источников у одного сериала, у каждого свой профиль конструктора | Упаковка дорожек в контейнер, Plex (этап 11) |
| Озвучки из всех плееров всех источников, группы озвучек | Референс-склейка (видео на несколько серий в роли референса) |
| Окно сериала: «Источники» и «Выход»; окно добавления | Логика, опирающаяся на длительность строки |
| Миграция схемы БД | Перевод существующих сериалов VK и сайтов на новую архитектуру с прежним поведением; переписывание их профилей правил |
| — | Нарезка склеек VK по главам (модуль `slicing` не участвует) |
| — | Приоритет разрешений пользователя (`vk_quality_priority`) |

## 3. Сущности

| Сущность | Определение | Владелец данных |
|---|---|---|
| Сериал | единица медиатеки: название, папка, сезон по умолчанию, память отключённых серий и сезонов | `catalog` |
| Источник сериала | адрес страницы сайта (или канал VK с запросом), привязанный к сериалу; несёт свой профиль конструктора и свой выбор (сезон каталога Vibix, отключённые плееры) | `catalog` |
| Таблица страницы | всё, что сайт и его плееры отдают по одной странице: шапка и строки; одна на страницу, общая для всех сериалов и потребителей | `sources` |
| Плеер | технический вид проигрывателя: `vk`, `allvideo`, `vibix`, `kodik`, `cvh`; у VK-канала — `vk` | `sources` (код плееров) |
| Строка таблицы | один элемент списка одного плеера так, как его отдал сайт: текст, группа плеера (сезон в его записи), озвучка в записи плеера или сайта, ступени разрешения, состояние | `sources` |
| Строка для конструктора | текст, собранный из полей строки таблицы одной общей функцией; единственный вход конструктора | контракт `core/contracts` |
| Раскладка сериала | результат прохода строк всех источников сериала через конструктор и группы озвучек: у каждой строки — сезон, серия или диапазон, часть, группа озвучки либо «исключена» | `composition` |
| Группа озвучки | имя и список названий (триггеров), по которым озвучка из любого источника относится к группе; заводится пользователем | `voices` (настройки) |
| Неизвестная озвучка | озвучка, имя которой не попало ни в одну группу; показывается как «Неизвестная озвучка N» | `composition` |
| Настройки выхода | значения рычагов на уровнях сериала, сезона и серии; у каждого рычага — «как уровнем выше» или своё значение; итоговые настройки серии — результат наследования | `composition` |
| Референс серии | одно видео одиночной серии, по которому выполняется conform; лежит в медиатеке | `scan` (план), `downloads` (файл) |
| Озвучка серии | видео той же серии (или склейки, покрывающей её) в другой группе озвучки; скачивается не выше 720p и после conform становится дорожкой рядом с референсом | `voices` |

## 4. Законы этапа

| № | Закон |
|---|---|
| З-1 | **Одна таблица.** Чтение сайта одно и то же для всех операций: окно добавления, окно сериала, тест правил, скан, озвучки. Других путей чтения сайта нет |
| З-2 | **Таблица полная.** В таблице все строки всех плееров страницы и разрешение каждой строки. Плееры не пропускаются из-за того, что лучшее разрешение уже найдено |
| З-3 | **Номера только от конструктора.** Номер серии, номер сезона, диапазон и часть появляются только как ответ конструктора на строку источника с назначенным профилем. Парсер, плеер, раскладка, окно и озвучки номеров не вычисляют. Строка, которую конструктор исключил, в раскладку не попадает |
| З-4 | **Один путь.** Таблица → конструктор → группы озвучек → раскладка → все потребители. Урезанных путей «только чтобы показать» нет |
| З-5 | **Каждой операции своё место.** Каждая функция живёт ровно в одном модуле-владельце; дубли удаляются. Новая функция, меняющая поведение существующего блока, вводится перестройкой этого блока, а не обёрткой или веткой сбоку |
| З-6 | **Группы озвучек — только пользовательские.** Без группы озвучки не склеиваются ни по написанию, ни по составу имени |
| З-7 | **Референс — одиночная серия** с наибольшим разрешением; при равном разрешении — плеер выше в приоритете. Пользователь может выбрать референс вручную на сериал или на серию |
| З-8 | **Длительность — справка.** Длительность строки хранится, но решения по ней не принимаются |

## 5. Требования

Столбец «Проверка» ссылается на измерения `VERIFICATION.md`.

### 5.1. Источники и таблица

| № | Требование | Проверка |
|---|---|---|
| Т-1 | Сериал имеет один или несколько источников; источник добавляется и удаляется в окне сериала. Торрент-сериалы ведут себя как прежде. Существующие сериалы VK и сайтов прежнего поведения не сохраняют: после миграции они видны, удаляются штатно, файлы медиатеки не затрагиваются; пользователь добавляет их заново (`DECISIONS.md`, Д-35) | М-1, М-12, М-20 |
| Т-2 | Таблица страницы строится по запросу и хранится в БД со временем чтения; пока с последнего полного чтения прошло меньше часа, страница не читается повторно; счётчик ведётся на каждую страницу | М-2, М-3 |
| Т-3 | Таблица публикуется потребителям только прочитанной полностью; неудача чтения сообщается с причиной, и действует прежняя полная таблица | М-4 |
| Т-4 | Одну страницу в каждый момент читает один процесс чтения; остальные запросы ждут сигнала готовности и сайт не читают | М-5 |
| Т-5 | Состояние каждой строки — одно из: играет (со ступенями разрешения), нет, не получено (ответ не получен за отведённые попытки); «не получено» не равно «нет» | М-6 |
| Т-6 | Сайт `1.ruchime.org`: строки списка серий страницы релиза с текстом сайта; плееры страницы серии VK, AllVideo, Kodik и каталог Vibix; озвучка строки — озвучка сайта, указанная на странице релиза | М-7 |
| Т-7 | Сайт `dunhuatv.ru`: плееры CVH и Kodik; у каждого плеера — все озвучки с именем, извлечённым способом этого плеера; группа плеера (сезон) и текст строки — как их отдаёт плеер | М-8 |
| Т-8 | Канал VK: строки — видео канала по запросу; текст строки — заголовок видео; озвучки у строки нет, её назначает конструктор | М-9 |
| Т-9 | Выбор, сделанный пользователем по источнику (сезон каталога Vibix, отключённые плееры), хранится у источника сериала, а не в адресе | М-10 |

### 5.2. Конструктор и раскладка

| № | Требование | Проверка |
|---|---|---|
| Т-10 | Каждому источнику назначается свой профиль конструктора (один профиль может стоять у нескольких источников) | М-11 |
| Т-11 | Строка для конструктора собирается одной общей функцией по единому образцу из полей строки таблицы: название релиза, плеер, озвучка, тип озвучки, группа плеера, разрешение, текст строки (`DECISIONS.md`, Д-30); тест правил показывает ровно эти строки | М-11 |
| Т-12 | Конструктор принимает строки с ключами и отвечает по ключу; ответ — единственный источник номеров для композиции, скана, озвучек, окна, имени файла | М-12 |
| Т-13 | Пока профиль источника не назначен, у его строк нет номеров; окно показывает число плееров, число строк и сезонов у плеера и разрешения | М-13 |
| Т-14 | Раскладка пересчитывается сама при новой таблице, добавлении и удалении источника, смене профиля или его правил, смене групп озвучек | М-14 |

### 5.3. Озвучки и группы

| № | Требование | Проверка |
|---|---|---|
| Т-15 | Озвучка строки относится к группе, если её имя совпадает с триггером группы без учёта регистра и пробелов; иначе — «Неизвестная озвучка N», номер постоянен для того же имени в том же сериале | М-15 |
| Т-16 | Имя озвучки строки: назначенное конструктором (действие «назначить озвучку»), если правило его назначило; иначе — имя от плеера или сайта; у VK-канала имя есть только из конструктора. Назначенное конструктором главнее всего (`DECISIONS.md`, Д-37) | М-15 |
| Т-17 | Озвучка серии берётся из строк своей группы, покрывающих серию; плееры перебираются по приоритету; не скачалась — следующий плеер; не скачалась нигде — серия без этой озвучки, причина видна у серии и в журнале | М-16 |
| Т-18 | Склейка-озвучка (строка с диапазоном) скачивается один раз и отдаётся в conform с референсом каждой серии своего диапазона | М-17 |
| Т-19 | Озвучки скачиваются не выше 720p (ближайшее разрешение, если 720p нет) | М-16 |

### 5.4. Референс

| № | Требование | Проверка |
|---|---|---|
| Т-20 | Референс серии — строка одиночной серии с наибольшим разрешением среди всех источников; при равном разрешении — плеер выше в порядке приоритета источников | М-18 |
| Т-21 | Строка-склейка референсом не становится; серия, покрытая только склейкой, показывает ошибку «референс не подходит»; правило действует и для сериалов, у которых склейка сейчас стоит в плане | М-19 |
| Т-22 | Ручной выбор референса — на сериал, на сезон и на серию (группа озвучки, источник, плеер); хранится в настройках выхода в терминах серии и переживает новое чтение таблицы. Если у выбранного плеера нет одиночной строки серии, берётся следующий плеер той же озвучки по правилу Т-20, и серия помечается «другой плеер» | М-21 |
| Т-23 | Серия без кандидата в референс — в состоянии «нет референса» с причиной; озвучки этой серии не скачиваются; выход из состояния — ручной выбор или появление кандидата | М-22 |
| Т-24 | Появился кандидат выше по разрешению — референс заменяется, дорожки прежнего референса убираются, озвучки выравниваются заново (поведение Р-37, Р-42 сохраняется) | М-23 |
| Т-25 | Референс скачивается в максимально доступном качестве | М-18 |
