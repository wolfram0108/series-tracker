## Протоколы

| Приложение | Протокол | Чем отличается от App99 |
|---|---|---|
| 半日 → **App99** (встроено) | App99 | — |
| 华谊 | AppDrama | хост из конфигурации-навигатора; обмен ключом зоны; запросы `POST /api/proto/v5/…`, ответы — свой протобуф и AES, ключ — RSA PKCS1 v1.5 |
| 橘汁 | AppDrama | тот же клиент, другой профиль |
| 茉莉 | AppGet (семейство Qiji) | `getappapi.index`, подпись запросов заголовками |
| 咕噜 | свой | ECC, HMAC, zlib, протобуф |

Модель данных у всех одна: **карточка → линии → серии с токенами → разбор токена в адрес потока**. У AppDrama
карточка — `drama/getDetail` (у видео `source` — код линии, `source_cn` — название, `title` — подпись серии,
`path` — токен, `is_vip`); разбор — `videoUsableUrl` (`vodPlayFrom` — линия, `playUrl` — токен) → адрес и заголовки.

вызовы App99 напрямую.

## Варианты объединения плееров

| Вариант | Плеер строки | «Порядок источников» | Признание |
|---|---|---|---|
| А. Линия приложения | `<приложение>:<код>` (как сейчас у App99) | отдельная позиция у каждой пары приложение + линия | по паре |
| Б. Линия как ресурс | `<код>`: один плеер на код во всех приложениях; приложение для разбора берётся из ссылки строки | одна позиция на код | по паре; позиция есть, если код признан хотя бы в одном приложении |

Вариант Б даёт одну позицию «bfzym3u8» вместо трёх и согласуется с тем, что строки одного видео (одинаковый токен)
уже узнаются системой как одно видео (`video_of`). Риск Б — разные ресурсы под одним кодом в разных приложениях:
выявляется сверкой токенов и хостов при признании.

**Решение владельца (2026-11-11): вариант Б** — один плеер на код линии для всех приложений; признание — по паре приложение + линия.

## Порядок работ по AppDrama

1. Клиент AppDrama на общем интерфейсе; App99 переводится на тот же интерфейс (без изменения поведения).
2. Вектора протокола из прототипа (шифрование, протобуф) — тесты на неизменных данных.
3. Опись и признание линий 华谊 и 橘汁: первая, центральная и последняя серия каждой линии целиком; реестры
   `admitted/huayi.json`, `admitted/juzi.json`.
4. Замер темпа получения серий (строк в секунду) на нескольких строках.
5. Модель протокола в тестах по снятому поведению; сторож договора на стенде.
6. Выкатка; проверка на нескольких строках; одна серия насквозь.
