# Этап 13.1 — источник 半日 (приложение App99): требования

Дата: 2026-11-11. Состояние: действует. Прогресс: 0 — блок делается заново (готовность источников приложений владелец обнулил повторно 11.11).
Слова владельца дословно — [ЭТАП_13.1.md](ЭТАП_13.1.md). Общий договор источника — [contracts/source_contract.md](../../../../contracts/source_contract.md).

Источник: видеоприложение 半日 (протокол App99). Карточка приложения — источник сериала, её серии по линиям — строки таблицы. Цель — референсы и эталоны вплоть до 2160 в общем пути сериала: таблица → конструктор правил → выбор референса и озвучек → загрузка → файл в библиотеке.

## Поток данных

| № | Требование |
|---|---|
| 1 | Путь строки: разбор → таблица → конструктор правил. Внутри таблицы признанной линии разбор ничего не отсеивает, не фильтрует и не угадывает: каждая серия, которую дала линия, — строка; признак приложения или линии — видимое поле строки. |
| 2 | Текст строки — подпись серии, как её дало приложение («第N集», «N», «PV»). |
| 3 | Одна запись сущности везде: что в строке, то и в любом другом месте. Адрес источника — `app://banri/<карточка>`; в шапке источника — название от приложения. |

## Линии и плееры

| № | Требование |
|---|---|
| 4 | Линия признаётся плеером, только если с неё получены целиком три файла: первая, центральная и последняя серия. Каждый файл проверен: кадр, разрешение, звук, длина. Доказательство (карточка, три серии, размер и разрешение каждого файла, дата) записано в реестр линий приложения; без записи линия не плеер. |
| 4а | Признанная линия ещё и читается таблицей: при чтении её карточки кодом сервиса (последние 10 серий) каждая строка получает разрешение своей серии. Линия, строки которой таблица измерить не может, — не плеер; причина в реестре — ответы этих строк. |
| 5 | Признание — на линию приложения (код линии один во всех карточках приложения). Центральная серия — средняя по списку серий линии в карточке, последняя — последняя в списке. |
| 6 | Линия, с которой поток не получен, выброшена: её серии не становятся строками таблицы, в «Порядке источников» её нет. Журнал чтения называет пропущенные линии карточки и причину. |
| 7 | Каждая признанная линия стоит в «Порядке источников»; пользователь ставит её выше или ниже. Линия называется своим кодом в приложении (CO4K, NBY, lzm3u8…) — в строках, в «Порядке источников», в журнале; китайское название линии — видимое поле строки, не имя. |
| 8 | Ссылка строки постоянная: карточка + линия + токен серии, не одноразовый адрес потока. |

## Разрешение

| № | Требование |
|---|---|
| 9 | У каждой строки — разрешение её собственной серии, измеренное по картинке. |
| 10 | Перенос разрешения на другие строки запрещён. |
| 11 | Строка без разрешения в конструктор не попадает; источник, у которого такие строки остаются, недопустим. Разрешение не измеряется в фоне после показа строк: таблица готова, когда измерены все строки. |
| 11а | Нет разрешения — значит, нет видео, значит, серии в источнике нет: это не допустимый итог чтения, а отсутствие серии. Строка кончается одним из двух: разрешение своей серии или «серии нет» с последним ответом хоста; состояния «не измерено» у строки приложения нет. |
| 11б | Неясный ответ итогом не записывается. Обрыв соединения, тайм-аут, 429 и 5xx хоста, отказ парсера, который проходит при повторе, переспрашиваются по общему правилу повторов плееров; каждый повтор — новый разбор серии приложением. Что осталось неясным под нагрузкой чтения всей карточки, проверяется после основного прохода: строки одной линии с одной причиной — один вопрос, на него отвечает повторный запрос одной из них. Тот же ответ — путь не работает (хост не принимает соединение), остальные строки причины повторно не спрашиваются; другой ответ — мешала нагрузка, и все строки причины спрашиваются снова, по нескольку. Чтение показывает это отдельной фазой со своим счётчиком («Повторный запрос строк без ответа: N из M»). Окончательный ответ (404; заглушка вместо начала файла) спрашивается один раз. |
| 11в | Мерится первый сегмент самого фильма — того, что сохранит загрузчик (чужая вставка перед фильмом в счёт не идёт). Файл, у которого хранилище отдаёт заглушку вместо начала, повреждён: серии нет, даже если середина цела. |
| 11г | Плейлист серии спрашивается у хоста один раз за замер: хост, который строит плейлист заново на каждый запрос, на второй может ответить отказом. |
| 12 | Если признанная линия на серии не дала поток, строка называет настоящую причину (реклама вместо серии, отказ соединения с хостом, 403 от CDN, не плейлист), а не общую формулировку. |

## Скорость и запросы

| № | Требование |
|---|---|
| 13 | Темп чтения — 20–30 строк в секунду. |
| 14 | Таблица моложе часа отдаётся из БД без запросов к приложению. |
| 15 | Разрешение, измеренное на строке, повторно не спрашивается: следующие чтения спрашивают только новые серии. |
| 16 | Результат разбора серии живёт час: загрузка в этот час идёт по уже полученному адресу. Адрес, который хост больше не отдаёт, разбирается заново один раз. |
| 17 | Число запросов к чужому серверу считается до кода. Проверки — на нескольких строках; массовые прогоны — только по слову владельца и в его объёме. Свойства сервиса утверждаются только по наблюдённым ответам. |

## Надёжность

| № | Требование |
|---|---|
| 18 | Ни один ответ не держится в памяти целиком сверх потолка. |
| 19 | Число одновременных ffprobe ограничено. |
| 20 | Чтение источника останавливается кнопкой в карточке источника. |
| 21 | Прерванное чтение не уводит прод в петлю перезапусков. |

## Поток и загрузка

| № | Требование |
|---|---|
| 22 | Файл или плейлист — по ответу хоста, а не по виду адреса и не по заявленному типу содержимого (хосты отдают плейлист как `image/png`, MP4 как `image/jpeg`): по сигнатуре в начале ответа — `#EXTM3U` плейлист; `ftyp` (MP4), транспортный поток MPEG, Matroska, FLV — файл; всё прочее — не поток, строка называет, что отдал хост. |
| 23 | Загрузка — та, что даёт лучший результат, вплоть до 2160; метод — как в прототипах владельца (`/home/user/source-prototypes/chinese_sources`): снимок плейлиста своим клиентом, загрузчик HlsFD. |
| 24 | Готовый файл проверяется: кадр, звук, длина. |
| 24а | Загрузка серии — 20–30 Мбит/с: загрузчик оптимизирован под эту скорость. Это требование к загрузчику, а не условие признания линии; скорость каждой загрузки признания записывается как замер. |
| 24б | Параллельных частей одного файла — не больше 16: служба качает несколько файлов одновременно. |

## Модель приложения в тестах

| № | Требование |
|---|---|
| 25 | Модель воспроизводит поведение настоящего 半日, снятое на нескольких строках: рекламный ролик вместо серии; отказ соединения с хостом; 403 от CDN; переадресация 302; MP4 без расширения; HLS с AES-128; пустой ответ парсера (code 0 без адреса); линия без разрешённого парсера; хост отдаёт не плейлист; задержка ответа 0,5–8 с. Новое поведение сначала снимается на нескольких строках, затем входит в модель. |

## Порядок работы

Опись поведения настоящего сервиса на нескольких строках → модель → тесты → код → один прогон затронутого → выкатка → одна живая проверка на нескольких строках.
