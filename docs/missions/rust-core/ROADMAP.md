# ROADMAP — Ядро пересчёта сериала на Rust

> Слой 2. Обновляется по ходу. Тонкий: текущее состояние, не вся история. Перед локальной работой — trace-up к CHARTER.

## ГДЕ СЕЙЧАС (2026-11-19)

Этап 0 закрыт. Ядро в репозитории (`native/`), собирается из git (`native/build.sh` → `core/_native.so`) от
пользователя сервиса; ядро читает строки раскладки из таблицы модуля и совпадает с модулем на всех сериалах копии
базы. Подготовлено на Python: план и раскладка без повторной работы, раскладка уходит планировщику моделью, вид плана
— проекция, `LAYOUT_PARTS`, `VIEW_INPUTS`, хранимые статусы на старте.

## РЕШЕНИЯ ЭТАПА 0 (2026-11-19, по замеру `native_check.py rows` на копии базы прода)

- **Строки попадают в ядро так: часть ядра, принадлежащая модулю, читает его таблицу сама.** SQL таблицы
  `composition_rows` живёт в `native/composition` — это часть модуля раскладки, Р-7 соблюдён. Замер, все 34 сериала
  (31 753 строки, 0 расхождений с модулем):

  | способ | все сериалы | сериал 46 (9 834 строки) |
  |---|---|---|
  | модуль сам (модели pydantic) | 880 мс | 281 мс |
  | модуль читает `sqlite3`, ядро получает кортежи | 281 мс | 97 мс |
  | ядро читает таблицу само | 139 мс | 32,5 мс |

  Пока модуль пишет строки на Python, одно знание (список столбцов) живёт в двух языках; сторож —
  `tests/test_native.py`. С этапом 1 модуль читает строки только через ядро.
- **Код ядра:** рабочее пространство `native/`, crate на владельца данных (`composition`, далее `planner`) на чистом
  Rust со своими `cargo test`, и один crate привязки `python` → модуль `core._native`. Как и модули Python, crate
  одного владельца не зависит от crate другого; общие типы — в общем crate, когда он понадобится.
- **Сборка:** `cargo build --release --locked` с копированием `.so` (`native/build.sh`), без maturin; `Cargo.lock` в
  git; rustc и cargo — из apt; собирает пользователь сервиса, кэш crates — в его `~/.cargo`.

## ТУПИКИ (НЕ повторять)

- **Пул процессов по шагам.** Передача раскладки или входов плана в другой процесс (pickle туда и обратно) стоит
  столько же, сколько сам счёт: 340 мс против 90 мс на сериале 40.
- **Перенос одной функции поверх объектов Python.** Выбор референса на Rust занимает 1–2 мс против 24–153 мс
  на Python, но перевод объектов в столбцы — 19–103 мс. Вместе с границей выходит не быстрее Python, а в потоках
  медленнее: перевод идёт под GIL.
- **Строки без проверки (`model_construct`).** Медленнее проверки pydantic: 812 мс против 508 мс на 31 753 строках.
- **Инкрементальный пересчёт.** Отвергнут владельцем: хрупок для расширяемости.
- **Переписывание шины.** Шина передаёт ссылки и в профиле не видна.
