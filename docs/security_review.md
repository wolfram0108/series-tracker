# Постановка задачи: поиск уязвимостей series-tracker

> Состояние: актуально на 2026-11-14. Жанр — ТЗ: требования к работе и её приёмке.
> Связано: [security.md](security.md) — модель угроз и выполненные этапы защиты;
> [deployment.md](deployment.md) — стенд, выкладка и проверка на живом сервисе.

---

## 1. Объект и заказчик

Заказчик — владелец системы, он же единственный администратор. Объект — этот
репозиторий и собранный из него сервис: один asyncio-процесс, шина, модули,
gateway, фронт `web/dist`.

| Слой | Что входит в проверку |
|---|---|
| gateway | FastAPI :5000, все HTTP/SSE-маршруты, вход, сессия, куки, заголовки, статика, `/legacy` |
| шина и модули | конверты, request/reply, разграничение данных между модулями |
| источники | разбор страниц, карточек и плееров; адреса и заголовки из ответов |
| загрузки и нарезка | `yt-dlp`, `ffmpeg`, имена и пути файлов, HLS-плейлисты |
| БД | схема, миграции, шифрование секретов, права файла |
| конфигурация | `.env`, systemd-юнит, nginx, логи и дампы прогонов |
| фронт | экраны, обработка ответов, вывод строк источников |
| зависимости | закреплённые версии из `requirements.txt` |

Разрешение: работа ведётся владельцем на его машине и на стенде. Прод-сервис не
атакуется; данные пользователя не выгружаются.

## 2. Цель

Найти классы дефектов, при которых внешний вход или данные источника дают:
выполнение кода, доступ к файлам вне разрешённых каталогов, обход входа,
утечку секретов, подмену содержимого интерфейса, отказ штатной работе.

Не цель: проверка нагрузки и доступности, аудит сторонних сервисов, поиск
контента, оценка качества кода и стиля.

## 3. Модель нарушителя

| Нарушитель | Что имеет | Что проверяется |
|---|---|---|
| Гость без входа | сеть до приложения и reverse-proxy | обход замка, `/api/setup`, SSE, статика, legacy-фронт |
| Вошедший администратор | сессию | CSRF, повышение прав, опасные ручки, подмена данных |
| Владелец источника | подконтрольные ответы сайта, карточки, плеера | RCE, выход за каталог, SSRF, XSS через строки |
| Данные на диске | файлы медиатеки, торренты, дампы | симлинки, права, чтение чужих файлов процессом |
| Локальная сеть | доступ к qBittorrent WebUI и track-muxer | подделка запросов между своими сервисами |

## 4. Границы

В границах — своя система целиком, включая её соединения с сервисами владельца
(qBittorrent WebUI, track-muxer).

Вне границ:

- сторонние сервисы: источники контента, трекеры, TMDB — никаких атак, обхода
  защит, перебора и массовых запросов;
- прод под нагрузкой: DoS, фаззинг, перебор пароля по живому сервису;
- хост и сеть вне приложения: роутер, правила nginx, чужие процессы;
- данные пользователя: медиатека и БД — только чтение и только копия.

Найденное не используется вне работы и не публикуется; доказательство
воспроизведения — минимальное, без готового инструмента атаки.

## 5. Классы, подлежащие проверке

| Класс | Где искать в системе | Признак находки |
|---|---|---|
| Выполнение команд | аргументы `yt-dlp`/`ffmpeg`, имена файлов, HLS, заголовки | значение из ответа сайта становится командой, опцией или путём |
| Выход за каталог | имена из торрентов и карточек, нарезка, переименование, дампы | файл создан или прочитан вне каталога медиатеки |
| SSRF | `parse_url`, обложки, адреса потоков, track-muxer | запрос уходит на хост, заданный данными, а не профилем |
| Обход входа и сессии | middleware, `/api/setup`, SSE, статика, `/legacy`, подпись куки | действие без сессии или с подделанной сессией |
| CSRF | изменяющие запросы, `SameSite`, `Content-Type` | действие от имени администратора с чужой страницы |
| XSS | строки источников в карточке и таблицах, `v-html`, SSE | исполнение в контексте приложения |
| Секреты | `.env`, ключ Fernet, логи, дампы прогонов, ответы API, история git | секрет в ответе, логе, дампе или репозитории |
| SQL | `repository.py`, динамические имена таблиц и колонок, миграции | значение данных меняет текст запроса |
| Разбор форматов | JSON, XML, bencode торрентов, архивы, регулярки | разбор падает или исполняет содержимое |
| Зависимости | `requirements.txt`, используемые функции | известная уязвимость в вызываемом коде |
| Отказ штатной работе | один ответ источника, размер, путь | один внешний ответ выводит сервис из строя |

## 6. Что считается находкой

- Сценарий: предусловие → шаги → результат → влияние (какие данные или
  действия получены).
- Класс дефекта и **все его носители** в коде: находка закрывается классом, а
  не одним местом.
- Воспроизводимость: прогон или тест, который падает до исправления и проходит
  после; штатный путь при этом работает.
- Severity по влиянию:

| Severity | Влияние |
|---|---|
| critical | выполнение кода; чтение секретов; запись или удаление вне каталога медиатеки; вход без пароля |
| high | действия администратора из сети без его участия; утечка сессии или секрета в лог, дамп, ответ; SSRF на произвольный хост |
| medium | SSRF в известные хосты; XSS, требующий действия администратора; подделка отображаемых данных; отказ одной операции |
| low | защитные заголовки, тексты ошибок, шум в журнале |

Не находка: теория без воспроизведения; дефект, для которого уже нужен root или
администратор, если это не повышение привилегий; стиль кода.

## 7. Как проверяется

- Белый ящик: чтение кода по слоям (gateway → модули → внешние вызовы → фронт),
  затем проверка гипотез на стенде.
- Каждая гипотеза — отдельный прогон с сырьём (запрос, ответ, журнал) в файле,
  чтобы вывод можно было перепроверить.
- Стенд: собранное приложение с копией схемы БД и моделями внешних сервисов
  (`tests/app_stand.py`, `tests/ui_stand.py`); прод не используется.
- Статический скан (`bandit` и подобные) — вспомогательный: находка без
  сценария не считается.
- Тяжёлые прогоны — под пределом памяти, с предохранителем; внешние сервисы —
  только штатными запросами.

## 8. Приёмка

- Каждый класс из §5 закрыт: либо находка, либо запись «проверено, не
  воспроизводится» с указанием, чем проверено.
- Исправление перечисляет носители класса и закрывает их одним законом.
- Тест-репродьюсер падал до исправления и проходит после; штатный сценарий
  работает.
- Инструменты, созданные для проверки, внесены в [реестр](../tools/INDEX.md)
  или удалены.

## 9. Результат

Отчёт `docs/security_findings.md`: таблица находок (severity, сценарий,
влияние, носители, исправление, статус), проверенные классы без находок,
журнал прогонов. Исправления — отдельными коммитами после согласования
класса. Отчёт внутренний, наружу не публикуется.
