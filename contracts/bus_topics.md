# Карта топиков шины (после этапа 10, П-8, 2026-11-01)

> Сводный справочник: что есть на шине и кто владелец. Детали payload'ов — в докстрингах `modules/*/module.py`
> (читать первыми) и в моделях `core/contracts`; решения — `contracts/revision.md` и
> `docs/missions/voice-alignment/stage-10/REVISION.md`. Перечень снят с кода (вызовы `handle` и `publish_event`),
> описания — из докстрингов модулей. Контракт шины: подписчик получает каждое подходящее сообщение один раз, в порядке
> публикации; сообщения не переживают перезапуск, поэтому обработчики идемпотентны, а продолжение работы берётся из БД.
> Каждый конверт несёт `correlation_id`.

## Запросы и команды по модулям

Запрос отвечает значением; команда ответа не ждёт. Отказ запроса — исключение владельца: текст `ValueError` — код
причины (`core/reasons`, формулировку даёт интерфейс), `LookupError` — «нет такой сущности».

| Модуль | Топики |
|---|---|
| catalog | `catalog.series.list` → `[{…сериал, kind, sources, statuses, is_busy}]`; `catalog.series.get {series_id}` → то же для одного; `catalog.series.create {data}` → сериал (`data.sources` — минимум один источник; отказ `no_source`, `source_exists`; поля `url`, `source_type`, `parser_profile_id`, `vk_search_mode`, `vk_quality_priority` у сериала удалены — отказ с именем поля) + `series.added`, затем `series.source.added` на каждый источник; `catalog.series.update {series_id, fields}` → `{applied}` (источники здесь не меняются) + `series.updated`; `catalog.series.delete {series_id, delete_from_qb?}` → `{ok}` + `series.deleted` (каскад по событию); `catalog.series.set_save_path {series_id, save_path}` (пишет library после переноса в синхронизации); `catalog.series.touch_scan_time`; `catalog.viewing.start/stop {series_id}` (команды); **источники сериала (Д-38):** `catalog.sources.list {series_id}` → `[источник]` по `position`; `catalog.sources.by_profile {profile_id}` → источники всех сериалов; `catalog.sources.add {series_id, source}` → `{id}`; `catalog.sources.update {source_id, fields, series_id?}` → `{applied}` (с `series_id` источник чужого сериала — `LookupError`); `catalog.sources.remove {source_id, series_id?}` → `{ok}` (единственный источник — отказ `last_source`; с `series_id` источник чужого сериала — `LookupError`); источник — модель `SeriesSource`; вид сериала `kind` (`torrent` либо `video`) считает одна функция каталога |

| rules | `rules.apply {profile_id, lines: [{key, text}], series_season?, rules?}` (с `rules` — правила профиля, какими их взял прогон: применяются они, а не сохранённые, И-60); `rules.profiles.export {profile_ids}` → `{profiles: {id: правила}}` (слепок прогона, `RunSnapshot.profiles`); → `{results: {key: {excluded, season, episode, start, end, part, voiceover, events, errors}}, invalid_rules}` — единственный источник номеров (З-3), модели `RulesApplyRequest/Reply`; `rules.format_filename {series, media_item, episode_override?, original_filename?}` → `{filename}` — имя по готовым номерам, правила повторно не применяются; `rules.format_torrent_file {series, profile_id, file_basename, original_path}` → `{filename, extracted}`; `rules.profiles.list/create/update/delete`, `rules.rules.list/add/update/delete/reorder` (профиль, назначенный источникам, удалить нельзя — `profile_in_use`) |
| composition | `composition.voice_order.set {series_id, season, labels}` → `{ok}` (порядок озвучек сезона, план: контейнеры следуют ему в синхронизации; во время прогона — отказ `not_allowed`); `composition.recompute {series_id, snapshot?}` — со `snapshot` (`RunSnapshot`) счёт прогона берёт правила и группы из него; `composition.get {series_id, include_excluded?}` → `CompositionReply` (описания рычагов `levers`: имя, вид цели, форма значения, умолчание; строки раскладки в порядке источников, сводка по источникам, рычаги сериала и сезонов, итоговые рычаги каждой серии; исключённые строки — только по `include_excluded`: исключённые конструктором (`rule`), без номера (`no_number`) и оставленные за бортом выбором источника — выключенный плеер, другой сезон каталога (`source`); scan и voices читают их, чтобы отличать решение пользователя от строки, которой нет в таблице, И-58); `composition.recompute {series_id}` → `{rev, changed}` (посчитать сейчас по хранимым таблицам и ответить, когда расчёт записан и событие вышло); `composition.preview {url?, profile_id?, series_season?, refresh?, lines?, players_off?, vibix_season?, voice_name?}` → `CompositionPreviewReply` — адрес, который ещё не источник сериала: состояние таблицы, сводка (число строк и сезоны каталога), строки для конструктора и ответ на каждую, строки раскладки, которые сделал бы профиль (`rows`, как у сериала; озвучек и разрешений в сводке нет) (ничего не пишет); с `lines` (набранные вручную названия или имена файлов раздачи) страница не читается, профиль применяется к этим строкам; `composition.settings.set {series_id, season?, episode?, lever, target?, value}` → `{ok}` (отказ `unknown_lever`, `bad_target`, `bad_value`); `composition.settings.reset {series_id, season?, episode?, lever?, target?}` → `{ok}` |
| scan | `scan.runs.get` → `{runs: [{series_id, snapshot}]}` — открытые прогоны синхронизаций по записанным командам, со слепком; исполнитель, запущенный заново, берёт их до своих работ (И-60); `scan.edit.begin {series_id}` → `{ok, token}` / `scan.edit.end {series_id, token}` (команда; повтор — то же, что один раз) — допуск изменения сериала пользователем: отказ `not_allowed`, пока синхронизация идёт или открывается; допуск держится, пока не отвечены все запросы правки, в том числе поздние после таймаута или обрыва вызывающего (core/admission.py: номер допуска в `Envelope.admission`); запрос с открытым допуском сериала scan не отклоняет как занятый (Н-14); допущенное изменение держит открытие прогона до своего конца (И-60); `scan.series.run {series_id, force_replace?, download?}` — торрент: проход по раздачам; видео: синхронизация источников (таблицы → раскладка → референсы → план → при `download` загрузки и озвучки), отказ `not_allowed` при скане той же серии; `scan.series.prepare {series_id}` (состав торрент-раздачи без закачки); `scan.output.get {series_id}` → `[Reference]` — референс каждой серии и отметка (`by_level`, `own`, `other_player`, `none`, `unfit`, `off` — серия отключена пользователем); `scan.output.switch {series_id, season, episode?, off}` → `{success}` — отключить или включить серию (без `episode` — сезон целиком; память сериала и строки плана меняются вместе, включение сезона включает в нём всё); `scan.all.start` → `{started}`; `scan.status.get`; `scan.media.list {series_id}`; `scan.media.downloaded_counts` → `{counts}`; `scan.seasons {series_id}` → `{seasons}`; `scan.item.set_ignored {unique_id, is_ignored}` (шлёт `slicing`; + `scan.plan.updated`, `scan.reference.changed` у изменившихся серий) |

публикуется и при подключении интерфейса `gateway.sse.clients`): сериал, ждущий своей очереди, и каждый слот — в очереди, собирается, собран, без изменений, ждёт загрузки, ошибка, прервана (запись журнала); `downloads.episodes.get {series_id}` → `{items}` — референс-серии плана, у каждой `file_rev` — номер файла строки (растёт, когда строка получает новый файл: опубликована загрузка или найден файл; пересборка контейнера — тот же файл); `downloads.items.rename {series_id, names}` → `{renamed}` — имена, которые план даёт готовым файлам сериала (все, неизменённые тоже): обязательство пишется до переноса, файлы переносятся (обмен и кольцо имён — через временное имя), имя записывается, когда файл под ним лежит; `downloads.item.set_filename`, `downloads.item.set_status` (нарезка); `downloads.fetch {key, url, path, max_height?, series_id?}` — поток по ссылке в файл вне медиатеки (озвучки, Р-40), остановка — по событию `work.withdrawn`; ## SSE

`SSE_MAP` шлюза (`modules/gateway/module.py`) — единственная таблица «топик шины → имя события интерфейса»; пакеты
событий самодостаточны для своего участка экрана, интерфейс ничего не доспрашивает. Контракт по каждому событию —
`contracts/sse_contract.md`. Модели пакетов этапа 10 (`TableProgress`, `TableReady`, `TableFailed`, `CompositionChanged`,
`CompositionFailed`, `ReferenceChanged`) шлюз кладёт в схему API рядом с маршрутами: типы интерфейса строятся из них.
