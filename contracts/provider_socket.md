# Розетка внешних источников (Provider Socket), протокол 1

Дата: 2026-11-14. Состояние: актуален. Жанр: спецификация. Владелец текста — этот репозиторий; поставщик в репозиторий
не входит и реализует спецификацию у себя.

## 1. Назначение

Трекер читает страницы и ищет названия только теми источниками, что встроены в него. Поставщик — отдельный необязательный
процесс, который отдаёт трекеру ещё одну группу источников через сетевую розетку. Без поставщика трекер работает целиком;
с ним в нём появляются: поиск названий, карточки как источники сериала, таблицы строк, плееры строк и потоки серий.

Первый поставщик — `chinese_sources` (видеоприложения с собственными API). Розетка от него не зависит: ни одно слово
протокола не называет приложение, протокол приложения или страну.

| Что делает поставщик | Что остаётся трекеру |
|---|---|
| поиск названий в своих источниках | хранение таблиц, срок их актуальности, события чтения |
| чтение карточки в таблицу строк, измерение кадра каждой строки | правила конструктора, порядок источников, планировщик |
| поток серии по ссылке строки перед загрузкой | загрузка файла по `stream_url` и заголовкам, нарезка, библиотека |
| свои секреты, темп запросов, память найденного | адрес карточки как источник сериала в БД, отключение плееров |

Поставщик не получает данных трекера: ни сериалов, ни настроек, ни секретов. Трекер не получает секретов поставщика.

## 2. Соглашения

- Транспорт: HTTP/1.1, тела JSON UTF-8, префикс путей `/v1`. Регулярные выражения — подмножество, общее для Python `re` и
  ECMAScript: классы символов, группы, именованные группы `(?P<имя>…)`, кванторы, якоря; без просмотра назад и флагов.
- Вход: если у поставщика задан токен, каждый запрос несёт `Authorization: Bearer <токен>`; отказ — `401`.
- Причина отказа — строка `{"code": "<код>", <факты>}` (`core/reasons.py`): код и факты, не предложение. Слова причины
  трекеру принадлежат (`web/src/i18n`); код, которого трекер не знает, показывается как есть. Словарь кодов — раздел 9.
- Лишние поля в запросах и ответах получатель игнорирует (добавление необязательного поля версию протокола не меняет),
  кроме таблицы (`TableDraft`, `TableRow`): её поля закрыты.
- Адреса источников поставщика — любой вид, который поставщик заявил в манифесте; для видеоприложений —
  `app://<приложение>/<номер карточки>`. Сохранённые в БД трекера адреса переживают смену поставщика: поставщик обязан
  читать адреса, которые он заявлял раньше.

## 3. Пути

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /v1/manifest` | — | `Manifest` (раздел 4) |
| `GET /v1/events` | — | поток событий (раздел 5): `text/event-stream` |
| `POST /v1/search` | `AppSearchRequest {query, page, app}` | `AppSearchReply {apps: [AppResults]}` (`core/contracts/apps.py`) |
| `POST /v1/read` | `ReadRequest` (раздел 6) | `application/x-ndjson`: кадры раздела 6 |
| `POST /v1/stream` | `StreamRequest {url, max_height, term_hours}` | `StreamReply` (раздел 7) |

Ответ вне `2xx` — отказ уровня протокола: `400` тело не разобрано, `401` токен, `404` пути нет, `5xx` сбой поставщика.
Отказ по существу (приложение не ответило, карточки нет, потока нет) — ответ `200` с причиной в теле.

## 4. Манифест

Манифест — всё, что трекеру нужно знать о поставщике без сети: какие адреса тот читает, какие плееры и источники поиска
имеет. Трекер сохраняет последний манифест в своей БД и при старте регистрирует по нему сайты, не дожидаясь поставщика.

```json
{
  "protocol": 1,
  "provider": {"id": "chinese_sources", "version": "1.0.0"},
  "revision": "5d41402abc4b2a76",
  "sites": [{
    "name": "banri", "label": "半日 (Banri)", "domains": ["banri"],
    "source_type": "web_video", "first_read_by_user": true,
    "address": {"schemes": ["app"], "path": "^/(?P<card>[0-9]+)/?$", "canonical": "app://banri/{card}"}
  }],
  "families": [{
    "name": "line", "label": "Линии приложений",
    "owns": "^app://(?:banri|huayi)/[0-9]+#line=(?P<line>[^&]+)&item=(?P<video>[^&]+)$", "video": "video"
  }],
  "players": [{"name": "line:CO4K", "label": "CO4K", "kind": "line",
               "places": [{"name": "banri", "label": "半日 (Banri)"}]}],
  "search": [{"name": "banri", "label": "半日 (Banri)"}]
}
```

| Поле | Смысл |
|---|---|
| `protocol` | целое; трекер принимает `1`, другое значение — поставщик отклонён (`provider_incompatible`) |
| `provider.id` | устойчивое имя поставщика; ключ сохранённого манифеста и подпись в журнале |
| `revision` | непрозрачная строка: меняется тогда и только тогда, когда меняется содержимое манифеста |
| `sites[]` | читатели страниц (раздел 4.1) |
| `families[]` | семейства плееров, которыми бывает строка таблицы (раздел 4.2) |
| `players[]` | плееры порядка источников и где они есть (раздел 4.3) |
| `search[]` | источники поиска: `name` — то, что называет `AppSearchRequest.app`, `label` — подпись; пустой список — поиска нет |

### 4.1. Сайт

Сайт читает страницу по адресу в таблицу (контракт `Site`, `modules/sources/sites/__init__.py`). Трекер находит сайт
адреса так же, как сайты реестра: сначала по домену, затем по виду адреса. Всё это — без сети.

| Поле | Смысл |
|---|---|
| `name` | имя сайта; уникально среди сайтов трекера и поставщика |
| `label` | подпись для человека |
| `domains` | хосты адресов сайта (хост адреса равен домену или его поддомену); хотя бы один |
| `source_type` | `web_video` либо `vk_video`: какой источник сериала делает страница |
| `first_read_by_user` | `true` — страницу, которую никто не читал, начинает команда пользователя; читать повторно её будет синхронизация (карточка приложения) |
| `address.schemes` | допустимые схемы адреса |
| `address.path` | регулярное выражение, которому целиком отвечает путь адреса; именованные группы — части каноничного вида |
| `address.canonical` | шаблон единственной записи адреса: `{группа}` подставляется из `path`; два адреса одной страницы дают одну запись |

Канонический адрес идемпотентен: канонический адрес, поданный как `url`, остаётся собой. Он — ключ таблицы страницы и
значение `url` в `ReadRequest`.

### 4.2. Семейство плееров

Строка таблицы принадлежит плееру по имени (`TableRow.player`): `<семейство>` либо `<семейство>:<что угодно>`. Семейство
задаёт то, чего трекер знает о ссылке строки без сети.

| Поле | Смысл |
|---|---|
| `name` | имя семейства; `player` каждой строки поставщика — это имя семейства или начинается с `<имя>:` |
| `label` | подпись |
| `owns` | регулярное выражение, которому целиком отвечает ссылка строки, принадлежащая семейству |
| `video` | имя группы `owns`, чей текст (после декодирования процентных кодов) — видео строки в нумерации хоста; две строки с одним видео — одно видео, откуда бы их ни показывали |

Поток ссылки, которой отвечает `owns`, спрашивается у поставщика (раздел 7). Ссылка семейства никогда не передаётся
общему загрузчику страниц: когда поставщик потока не даёт, ответ — отказ, а не «не моё».

### 4.3. Плеер порядка источников

| Поле | Смысл |
|---|---|
| `name` | имя плеера, как оно в строках (`line:CO4K`) |
| `label` | подпись |
| `kind` | `site` либо `line`; как плеер называет экран «Порядка источников» |
| `places[]` | `{name, label}` сайтов поставщика, где плеер есть и без чтения таблицы |

Трекер сам добавляет к каждому месту число источников, чьи сохранённые таблицы содержат строки плеера, и лучшее
разрешение его строк.

## 5. События поставщика

`GET /v1/events` — поток `text/event-stream`. Он открыт, пока жив поставщик; изменение состояния поставщика приходит по
нему, опроса манифеста нет.

| Событие | Данные | Когда |
|---|---|---|
| `hello` | `{"revision": "<строка>"}` | первым после подключения |
| `changed` | `{"revision": "<строка>"}` | манифест изменился (профиль добавлен или снят, признана линия) |
| `: keep-alive` | — | каждые 15 секунд: тишина дольше 45 секунд — мёртвое соединение |

Трекер при `hello` и `changed` сравнивает `revision` с сохранённой и, если она иная, читает манифест заново. Обрыв потока —
событие трекера `sources.provider.state {state: down}`; он открывает поток снова с возрастающей паузой (1 с → 30 с).

## 6. Чтение страницы

`POST /v1/read` отвечает потоком `application/x-ndjson`: один JSON на строку, порядок кадров — любое число `progress` и
`alive`, затем ровно один из `draft` и `error`.

Запрос `ReadRequest`:

| Поле | Смысл |
|---|---|
| `url` | канонический адрес страницы (раздел 4.1) |
| `rows` | сколько строк каждой линии читать: `all`, `N` — первые N, `-N` — последние N (`core/row_limit.py`) |
| `recent` | только стенд: брать последние столько серий каждой озвучки; `null` — вся страница |
| `fresh` | `true` — пользователь велел прочитать сейчас: добытое прошлым чтением в общее пользование не берётся |
| `off` | имена плееров, отключённых владельцем для всех источников: поставщик их не спрашивает и новых строк их не даёт |
| `last_rows` | строки последней полной таблицы страницы (`TableRow`): то, что плеер уже сказал о ссылке, называющей своё видео, повторно не спрашивается |
| `term_hours` | срок актуальности опроса источников в целых часах, как его задал владелец (`sources.term.get`): столько поставщик считает верным то, что узнал сам (адрес потока серии от парсера, хосты, настройки разбора); `null` — собственный срок поставщика |

Кадры:

| Кадр | Поля | Смысл |
|---|---|---|
| `progress` | `phase`, `current`, `total` | как далеко чтение; `phase` — один из `release`, `episodes`, `players`, `catalog`, `videos`, `recheck` |
| `alive` | — | поставщик жив, чтение идёт; шлётся, когда 15 секунд кадров не было |
| `draft` | `draft` | итог: `TableDraft {names, title, site_voice, channel, rows, unread}` (`modules/sources/sites/__init__.py`) |
| `error` | `reason` | отказ читать: причина-код (раздел 9); итога нет |

Правила:

1. Поток без `draft` и `error` на конце — отказ поставщика (`provider_stream_broken`); частичная таблица не принимается
   никогда.
2. Ключи строк (`TableRow.key`) уникальны в странице; `player` каждой строки — семейство или плеер семейства из манифеста;
   `video` строки поставщик может не заполнять: его определяет трекер по `families[].owns`.
3. Закрытие соединения клиентом — отмена чтения: поставщик обязан остановить работу над страницей и отпустить ресурсы. Для
   отмены отдельного вызова нет.
4. Один запрос — одно чтение. Сколько чтений идёт сразу и каким темпом спрашиваются хосты приложений — дело поставщика.
5. Прогресс не копится: поставщик сообщает последнее значение, а не каждое.

## 7. Поток серии

`POST /v1/stream` с `StreamRequest {url, max_height, term_hours}`, `url` — ссылка строки, которой отвечает `owns` семейства,
`max_height` — высота, выше которой файл не берётся (`null` — лучший), `term_hours` — как в разделе 6. Поток спрашивается непосредственно перед загрузкой:
адреса файлов недолговечны, трекер их не хранит.

`StreamReply`:

| Исход | Поля |
|---|---|
| поток есть | `handled: true`, `stream_url`, `headers` (заголовки запросов к потоку), `progressive` (готовый файл, отдаваемый частями), `playlist` (HLS-плейлист, качаемый по сегментам), необязательный `audio_url` (отдельный файл звука к видеофайлу, те же заголовки) |
| потока сейчас нет | `handled: true`, `error` (причина-код), `transient` — причина может пройти сама |

`handled: false` для ссылки, которой отвечает `owns`, — нарушение: трекер читает его как `provider_bad_answer`.

## 8. Состояния и сигналы трекера

| Состояние | Когда |
|---|---|
| `absent` | поставщик не настроен (`ST_PROVIDER_URL` пуст): ничего из розетки нет |
| `connecting` | манифест ещё не получен в этом запуске |
| `up` | поток событий открыт, манифест применён |
| `down` | поток оборван или тишина дольше 45 секунд; сохранённый манифест действует |
| `incompatible` | `protocol` манифеста трекер не принимает |

Состояние — событие `sources.provider.state {provider, state, revision?, reason?}` (владелец `sources`, `contracts/bus_topics.md`).

| Положение дел | Что делает трекер |
|---|---|
| поставщик `down` при чтении страницы | чтение кончается неудачей `provider_unavailable`; служит прежняя полная таблица |
| поставщик `down` при потоке | `StreamUnavailable(provider_unavailable, transient=true)`: загрузка уходит к следующему источнику |
| поставщик `down` при поиске | у каждого заявленного источника поиска причина `provider_unavailable` |
| сайт поставщика занимает домен или имя сайта трекера | сайт поставщика пропущен, в журнале причина |
| манифест перестал называть сайт | сайт снимается; таблицы его страниц забываются как таблицы страниц, не перечисляемых ни одним источником |
| поставщик `down` | сайты сохранённого манифеста не снимаются: таблицы их страниц не забываются |

## 9. Словарь причин

Коды, которые выдаёт трекер: `provider_unavailable` (поставщик не отвечает), `provider_incompatible` (`protocol` не принят),
`provider_stream_broken` (поток чтения оборван без итога), `provider_bad_answer` (ответ не по спецификации), `provider_refused`
(`401` либо `4xx` на запрос, который трекер счёл верным).

Коды, которые выдаёт поставщик чтения и потока: любой код из каталога причин трекера (`web/src/i18n/ru.ts`, ключи
`reason.*`) со своими фактами; уже заведены для видеоприложений `app_unreachable`, `app_status`, `app_refused`,
`app_answer_broken`, `app_title_absent`, `app_no_stream`, `app_no_parser`, `app_search_unavailable`,
`app_search_source_cooling`, `app_pagination_repeated`, `app_lines_not_admitted`, `app_share_gone`, `app_share_unlisted`,
`app_share_unlisted_partial`, `app_folder_too_large`, `app_folder_selection_required`, `player_failed`,
`player_video_missing`, `player_unconfirmed`, `player_status`, `player_no_answer`, `video_private`, `no_players_empty`,
`not_a_title_page`. Новый код поставщик заводит вместе со словами в каталоге трекера.

## 10. Сроки

| Число | Что оно | Где |
|---|---|---|
| 15 с | срок, через который поставщик шлёт `alive` или `: keep-alive` | обнаружение отказа |
| 45 с | молчание, после которого трекер считает соединение мёртвым (три срока) | обнаружение отказа |
| 1 с → 30 с | пауза повторного подключения потока событий, удваивается | темп восстановления внешней системы |
| срок запроса `sources.apps.search` и `sources.video.stream` | таблица `core/deadlines.py` минус запас | предохранитель |
| срок чтения страницы | предохранитель таблицы чтений трекера (`TABLE_READ_S`) | предохранитель; его срабатывание — отказ чтения, закрытие соединения — отмена |

Ни одно число не служит способом дождаться готовности: готовность и отказ приходят кадрами и событиями.

## 11. Гарантии

| Что | Гарантия |
|---|---|
| событие `hello` / `changed` | не менее одного раза после подключения и после каждого изменения; порядок сохраняется; обработчик идемпотентен (сравнение `revision`) |
| итог чтения | ровно один из `draft` и `error` либо обрыв потока, который трекер читает как отказ |
| отмена | закрытие соединения; исполнитель останавливается |
| перезапуск поставщика | трекер переподключается сам; прежние таблицы служат |
| перезапуск трекера | сайты сохранённого манифеста регистрируются до любого чтения |

## 12. Настройка

| Сторона | Переменная | Смысл |
|---|---|---|
| трекер | `ST_PROVIDER_URL` | адрес поставщика (`http://127.0.0.1:5100`); пусто — розетки нет |

## 13. Проверка

Соответствие поставщика спецификации проверяется без трекера: набор `tests/test_socket_*.py` поставщика ходит по путям
раздела 3 по настоящему HTTP. Соответствие трекера проверяется без поставщика: `tests/provider_mock.py` — модель поставщика по
этой спецификации, на настоящем HTTP, с управляемым поведением (медленное чтение, обрыв, смена манифеста, отказ потока, поставщик
вниз и вверх). Совместная проверка — стенд всего приложения с настоящим поставщиком над моделями приложений (`tests/app_stand.py`:
`test_source_contract.py`, `test_app_stand.py`, приёмка в браузере `test_ui_apps.py`) и сверка моделей провода у двух сторон
(`tests/test_provider_socket.py`); эти тесты пропускаются, когда поставщика на машине нет.
