# Паритет поставщика: что обязан отдать Чинес и что делает перенос, чтобы настроенные сериалы остались такими, какие есть

Дата: 2026-11-18. Состояние: актуален для протокола 2 (линия во главе, решение Р-109); редакция 14.11 (протокол 1, источник — карточка
двери) снята. Жанр: ТЗ. Протокол розетки — [provider_socket.md](provider_socket.md); обязанности источника —
[source_contract.md](source_contract.md).

## 1. Назначение

Критерий один: **ни один настроенный сериал не теряет ни файла, ни строки, на которую опирается его план**. Протокол 2 меняет то, как
называется источник и как называется строка: источник — название поставщика, не карточка двери; строка — ряд линии, не ряд двери.
Этот документ — что при этом сохраняется, что переписывается, и как принимается перенос.

## 2. Что сохраняется и что меняется

Файл библиотеки помнит своё видео тройкой `(источник, ключ строки, видео)`; источник — число (`series_sources.id`), его адрес в тройку не входит.

| Что | Протокол 1 | Протокол 2 | При переносе |
|---|---|---|---|
| Номер источника | `series_sources.id` | тот же | **сохраняется**: файлы остаются на своём источнике |
| Адрес источника | `app://<дверь>/<карточка>` | `title://chines/<id>` | переписывается (`series_sources.url`, `release_tables.url`, `release_rows.url`, `composition_sources.table_url`) |
| Видео строки (`video`) | жетон, один раз декодированный | жетон | **сохраняется**: жетон одной линии один через любую дверь |
| Ключ строки | `<дверь>:<линия>:<место>` | `<линия>:<место>` | переписывается по соответствию видео (`release_rows.key`, `composition_rows.row_key`, `plan_assets`, `plan_failures`) |
| `player` | `line:<код>` | `line:<код>` | не меняется |
| Ссылка строки | `app://…#line=<код>&item=<токен>` | `line://<код>/<токен>` | переписывается (`release_rows.link`, `composition_rows.link`, снимок `link` в `plan_assets`) |
| Сайт | имя двери | `chines` | `release_tables.site` |

Тождество строки поставщик строит этими формулами (provider_socket.md, раздел 2.1 и приложение A.2); отличие хоть в одной — осиротевшие файлы.

## 3. Что обязан отдать поставщик

Для каждого названия, на которое придёт источник сериала: ряды всех линий, которые сериал использует, с теми же жетонами, что давали
двери раньше; измеренное разрешение своего ряда; загрузку целой серии. Линия — плеер, только если признана поставщиком (КРИТЕРИИ его
прототипов: не менее трёх протоколов, поиск, список, разрешение, целая серия без дыр, доступность, реклама по сигнатуре блока).
Линия, которой поставщик не отдаёт, не плеер: её рядов в новой таблице нет, и файлы на них становятся осиротевшими — перенос на такой
линии не применяется, пока владелец не скажет иначе (раздел 5).

## 4. Перенос: усыновление

Инструмент `tools/adopt_titles.py` (разовый, удаляется в коммите выкатки вместе с `tests/test_adopt_titles.py`), по приложению B
provider_socket.md:

1. `POST /v1/adopt` — какому названию отвечает каждый старый адрес `app://…`; поставщик привязывает карточки доказательством (жетоны).
2. `POST /v1/read` каждого названия, все ряды.
3. Сопоставление строк по `(player, video)`: старый ключ → новый ключ и новая ссылка.
4. Одна транзакция: адреса и ключи переписываются во всех местах из раздела 2; два источника одного сериала, пришедшие к одному названию,
   становятся одним (остаётся первый, файлы второго переходят на него); производные таблицы композиции переписываются так же.
5. Строка старой таблицы, для которой у названия нет видео, — **потерянная**; пока на ней стоит хоть один файл плана, перенос **отказывает**
   и ничего не пишет (`--allow-orphans` — слово владельца).

Без `--apply` инструмент работает на копии базы и печатает, что изменится. С `--apply` сначала копия `app.db` в `backups/`, потом перенос.

## 5. Приёмка

Мерка — прод-БД как эталон (в копии). Делается владельцем после завершения разработки Чинеса, с подключёнными прототипами:

1. План (без `--apply`): ни одной потерянной строки, на которой стоит файл; `unadopted` пуст либо назван владельцем (источники вне линий:
   `share139`, `yunduo`, `bubu` и т.п.).
2. После переноса на копии: синхронизация каждого настроенного сериала не меняет план — ни пересборок, ни удалений, ни новых загрузок,
   кроме вышедших серий.
3. По одной серии каждой используемой линии загружается целиком: звук и картинка совпадают с серией, высота равна измеренной.
4. Перенос на боевую базу — осознанно, с бэкапом, при простое (docs/deployment.md).

## 6. Чего паритет не требует

Другого вида ответов, чем в provider_socket.md; того же числа потоков загрузки (оно — дело поставщика); совпадения высот там, где хост
изменил ответ; поиска публичных папок 139 Cloud и его памяти.
