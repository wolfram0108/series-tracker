Дата: 2026-11-14. Состояние: актуален. Жанр: ТЗ. Срез данных — прод-БД на 2026-11-14 (только чтение). Протокол розетки —
[provider_socket.md](provider_socket.md); обязанности источника — [source_contract.md](source_contract.md).

## 1. Назначение

Перечень и порядок того, что поставщик (Чинес) воспроизводит до выкатки розетки на прод, и мерка приёмки. Критерий один: ни один
настроенный сериал не теряет ни файла, ни строки, на которую опирается его план.

### 2.3. Подпись запросов appmn

Приложение appmn принимает карточку, поиск и билет потока только с подписью запроса; без неё отвечает `4604`. Клиент поставщика
обязан: открыть сессию обменом ключей P-256 (`POST /api/v1/security/init`); подписывать каждый запрос, кроме рукопожатия,
HMAC-SHA256 по девяти строкам (метод, путь, канонический запрос, хеш тела, секунды, одноразовый nonce, идентификатор устройства,
идентификатор сессии, версия приложения); читать ответ с `data.enc = 1` (AES-256-GCM); при кодах `4602`, `4603`, `4604` открыть
сессию заново и повторить запрос один раз. Реализация — у поставщика. Модель приложения
проверяет схему, но не доказывает, что приложение её приняло: принятие — живой ответ приложения (раздел 6).

## 4. В каком виде: тождество строки

Файл помнит строку, а не ссылку на сайт; поэтому поставщик строит строки **теми же формулами**. Отличие хотя бы в одной
формуле — осиротевшие файлы.

| Что | Формула |
|---|---|
| Сайт | имя приложения строчными (`banri`), хост адреса — то же имя |
| Адрес карточки | `app://<приложение>/<номер>`; адрес с `/` на конце и без — один; канонический — без неё |
| `key` строки | `<приложение>:<код линии>:<место>`; место — порядковый номер серии в полном списке линии, как его даёт приложение, с единицы; от предела строк оно не зависит |
| `player` | `line:<код линии>`; `player_label` — код линии |
| `text` | подпись серии, как её дало приложение (`1`, `第01集`, `《…》PV`), без правки |
| `link` | `app://<приложение>/<номер>#line=<код линии, процентное кодирование без безопасных знаков>&item=<токен серии, то же кодирование>` |
| Токен серии | собственное название видео у приложения, как оно пришло; не пересчитывается и не перекодируется |
| `video` | токен после одного декодирования процентных кодов из `item` (его делает трекер по `families[].owns`) |
| `state`, `heights` | `playable` с одной высотой измеренной по кадру собственного видео серии либо `absent` с причиной-кодом (provider_socket.md, приложение A.3) |
| `site_fields` | `app`, `line`, `line_name` (название линии у приложения), `parsers`, `stream` (`playlist` либо `parser`), `place`, `frame` (`measured`) либо `frame_failed` и `asked` |
| `title` | `<подпись приложения> · <первое название> (<год>)`; без года — без скобок |
| `names` | названия карточки в порядке приложения |
| Предел строк (`rows`) | `all`, `N` первые, `-N` последние, `A-B` с A-й по B-ю включительно — на каждую линию; не взятое трекер оставляет из прошлой таблицы сам |
| Повторное чтение | строки `last_rows`, у которых `frame` равен `measured`, не измеряются заново |

## 5. Загрузка

Для линий очереди 1 файл целиком, с звуком и длиной, как её назвал источник, по пути, который назвал трекер; высота в `done` — высота
картинки файла. Способ получения (части файла, сегменты плейлиста, пара файлов DASH, пересборка) выбирает поставщик. Поток,
который приходит парой файлов DASH — видео и отдельный звук (так описана линия CO4K в тестах поставщика; живой ответ сверяет
владелец), — файлом без звука не заканчивается: без звука нет `done`.

## 6. Приёмка паритета

Мерка — прод-БД как эталон. Приёмка делается один раз на линию и один раз на приложение владельцем, с настоящими приложениями:

1. Для каждого источника-приложения (57) поставщик читает карточку; в ответе нет ни одной потерянной строки из хранимой таблицы по
   линиям, которые поставщик отдаёт: ключи, `player`, `link` и `video` совпадают; высоты совпадают либо расходятся только там, где
   изменился ответ хоста (причина названа).
2. Каждая из 937 строк, на которые ссылаются файлы актива (раздел 2.1), есть в новой таблице с тем же ключом и тем же видео.
3. По одной серии каждой линии очереди 1 загружается целиком: звук и картинка совпадают с серией, высота равна измеренной.
4. После приёмки очереди 1 синхронизация каждого из четырёх сериалов (40, 46, 49, 50) не меняет план: ни пересборок, ни
   удалений, ни новых загрузок, кроме вышедших серий.

Выкатка розетки на прод — после приёмки очереди 1.

## 7. Чего паритет не требует

Другого вида ответов, чем в provider_socket.md; того же числа потоков загрузки (оно — дело поставщика); совпадения высот там, где хост
изменил ответ; поиска публичных папок 139 Cloud и его памяти (две строки `share139_folders`).
